# 千星奇域制作流程

完整制作、复杂修改和多阶段排障由qianxing-editor按 [阶段式制作](staged-production.md) 组织：现场→需求与验收→实现设计→最小闭环→小步实施→自查→组装回读→游玩检查与交付反馈。只辅助原神千星奇域；单点查询和小改动直接进入对应专责，不强走全部阶段。

已有授权继续实施，不逐阶段重复确认。读取当前输入、基底、用户保留项与交付形式；新需求由Agent设计并实际实现，既有合同读取兼容，只有缺少无法取得的必要输入或关键玩法选择时询问。

## 按当前任务进入

| 任务 | 工作流 |
| --- | --- |
| 职责与阶段交接 | [十项分工](skill-map.md)、[能力合同](capability-contract.md) |
| 一句话或完整关卡 | [完整关卡编排](one-sentence-workflow.md)、[主动实现](implementation-policy.md) |
| 事件、节点与严格编译 | [图设计](graph-authoring.md)、[节点图构建](node-graph-workflow.md) |
| 新基底、UI模板和Lua映射/挂载 | [参数化生成](native-authoring.md) |
| 素材、协议、动画、图与Lua整合 | [内部制作核心](production-core.md) |
| 位图或参数图形 | [统一素材](asset-generation.md)、[富文本分支](rich-text-assets.md) |
| 帧和已有分层数据动作 | [点阵运行时](pixel-runtime.md)、对应动画技能 |
| 操作反馈、输入与目标设备 | [体验与游玩检查](playability-workflow.md) |
| Lua逻辑、自检与日志 | [客户端模型](client-simulation.md)、[调试](debugging-workflow.md) |
| 文件和宿主证据 | [验证等级](validation.md) |

所有阶段共享同一需求、权威状态、协议、标识和证据，避免分别猜测信号或模板ID。完整新玩法先打通进入→操作→规则推进→结果→重开；单人不自动增加网络、原生3D不由Lua界面原型代替。

已有项目读取当前基底并保护用户改动；新项目在已支持结构范围内参数化生成，不克隆完整游戏。HTML、素材、动画与高级拟合按需参与，不要求用户挑选框架。所有工具和资料见 [完整索引](README.md)。

交付源码、GIA/GIL、必要资源和可定位报告。静态、编译、回读、挂载、模型、编辑器和实机分别记录，未验收项明确标注；不因缺少宿主工具停在计划，也不把离线产物称为已确认可玩。
