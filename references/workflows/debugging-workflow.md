# 调试与验收

按[验收说明](validation.md)选取与本次修改有关的检查，核对证据是否对应当前产物。

沿日志检查生命周期、根控件、模板实例化、输入绑定、客户端发送、服务端接收和回复。通信成功需要接收或回包证据。遇到 `nil` 父级或字段错误时，检查脚本初始化顺序和 `EnableUpdate`，保留模型的字段与类型检查。

存档按首次读取、实际业务更新、原生写入、内容回读、离场及重进首次读取逐段取证。先找出最早失败的步骤。收到回复时，核对回复字段能否确认本次写入。沿最终节点图的实际连接检查端口类型。图转换顺序、已知空档恢复和日志容器的适用范围见[原生数据流排障](../graph-code/native-dataflow-validation.md)。

先核对结构摘要、修改字段、内嵌 Lua、模板绑定、节点引用和信号参数。随后测试包去重、状态同步、资源消耗与恢复、超时和离线处理及动作回放。界面检查覆盖 PC、横屏手机和长屏，并用满席位与最长名称核对命中区域和背景覆盖。

回读 GE 图元时核对顺序、尺寸、旋转、RGBA、坐标空间和数量。比较原图与重建图的整体效果及局部边缘，再结合 RMSE 等指标判断画质。

手头有导出日志时用[日志诊断](log-diagnostics.md)，需要复跑 Lua 启动和模板加载时用[客户端模型](client-simulation.md)。产物与报告不一致时见[工程只读诊断](project-diagnosis.md)。
