# 调试与验收

先按 [验收说明](validation.md) 选检查层级。根据修改选最小有意义的检查，不把历史报告当当前版本通过证明。

从日志定位生命周期、根控件、模板实例化、输入绑定、客户端发包、服务器接收和回包；只有发送日志不能认定通信成功。调试脚本初始化顺序和EnableUpdate，不用过度宽松的mock绕过nil父级或错误字段。

存档按首次读取、实际业务更新、原生写入、内容回读、离场及重进首次读取逐段取证。先定位首个断点，有回包也要核对字段是否足以确认该次写入；最终图沿实际输出声明检查数据类型。图转换顺序、已知空档恢复及日志容器边界见 [原生数据流排障](../graph-code/native-dataflow-validation.md)。

检验结构hash与修改字段、内嵌Lua、模板绑定、节点引用和信号参数；再测业务不变量，如包去重、同步状态、资源消耗恢复、超时/离线和动作回放。界面检查PC、横屏手机、长屏、最大席位及最长名字，检查命中区与背景覆盖。

GE图元保持顺序，回读尺寸、旋转、RGBA、坐标空间与总数。用源图-重建对照和局部边缘诊断判断画质，不能用RMSE独自宣布合格。

手头有导出日志时用[日志诊断](log-diagnostics.md)，需要复跑 Lua 启动和模板加载时用[客户端模型](client-simulation.md)。产物与报告不一致时见[工程只读诊断](project-diagnosis.md)。
