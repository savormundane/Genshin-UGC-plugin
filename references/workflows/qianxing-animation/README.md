# 动画接入

以 [客户端API](../../../skills/qianxing-editor/references/client-controls-api.md) 和 [核心来源](../../sources-and-conflicts.md) 为依据。输入应为已生成的数据、其坐标空间及尺寸；缺少数据时先用 qianxing-assets 转换。普通按钮和窗口的 Tween 见 [Qianxing Editor 的 Client Lua 入口](../../../skills/qianxing-editor/SKILL.md#client-lua)。

## 点阵帧

先读 [点阵运行时](../../pixel-runtime.md)，需要算法背景时查 [核心像素指南](../../pixel-import-guide.md)。按最大帧建一套固定池，切帧更新已有控件，隐藏多余块；镜像围绕帧锚点，动作选择来自当前项目状态。输出宿主播放代码、数据内联方案与模板配置。

## 分层图元与拟L2D

按需读 [分层参考](../../l2d/README.md) 的04–06、10–11。需要拆层和拟合时把01–03交给素材阶段，不在动画阶段重复执行。旧07速查不高于核心API；核心API已说明Tween目标表。

核对部件遮挡、公共画布、锚点和统一坐标空间。父容器处理共同变换；局部形变用连续位移场避免接缝。呼吸、眨眼、视点和离散动作组合后能还原且互不抵消。只写核心API允许的Tweenable字段；对当前宿主的父级旋转、裁剪和alpha效果做最小验证。

以控件总量和每帧API写入量评估负载，缓存未变属性、隐藏非当前视角并限制初始化批量。不每帧全量写上万控件。原参考附件先复制到工作区、核对参数依赖与占位符，不作为任意角色的一键生成器，也不导出原生Cubism模型。

按 [验收标准](../../validation.md) 验证数据/动作/输入及性能，只报告本次证据；制作经验见 [经验库](../../production-experience.md)。

## 共享参考的读取时机

当前任务跨越两个以上开发阶段时，先读 [制作流程](../../production-workflow.md)，确认主入口、已有输入和阶段交付；单一接口查询无需加载完整流程。

排查报错、无响应、不同步或显示异常时，先读 [调试方法](../../debugging-workflow.md)，再按本技能负责的部分定位。修改后的检查按 [验收标准](../../validation.md) 选择有意义的范围；只报告本次执行的验证，不自动扩大成全面审计。


与其他制作阶段协作时按 [统一能力合同](../../capability-contract.md) 传递本技能的输入、输出及验证状态；完整玩法由 qianxing-editor 协调。

已有数据直接实现动作；数据不足时在同一任务内调用素材阶段补齐。动作状态、参数和生命周期由Agent设计并接入玩法事件，完成镜像/重开/销毁恢复；只有确需原图或缺少真实宿主接口时才询问。

新合同设计、既有内容兼容和缺项处理按 [主动实现约定](../../implementation-policy.md)。

制作与整合使用 [内部制作核心](../../production-core.md)：统一API检索、协议校验、帧数据、客户端支持及受保护Lua写回；先完成当前职责的实际实现，再通过同一produce入口交付。

动作帧保持公共画布、统一缩放和共同锚点，检查静止、切帧、镜像、动作切换和重开；表现读取玩法状态，不用动画完成回调替代权威结算。 具体方法见 [体验制作与游玩检查](../../playability-workflow.md)。

帧控件的对象复用、属性写入缓存与前台优先双预算调度使用 [UI运行支持](../../runtime-ui.md)；时钟暂停和按需资源释放使用 [通用算法模块](../../algorithms-experiments.md)。通过 [源码装配](../../client-assembly.md) 内联，不依赖宿主require。
