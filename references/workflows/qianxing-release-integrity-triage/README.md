# 千星奇域交付链完整性判读

用于千星奇域工程的源码、生成物、清单、验证报告和工具依赖排障。工程的文件名、版本策略、原生允许修改字段与构建命令由当前配置决定，不套用其他项目的约定。

先按[只读诊断](../../project-diagnosis.md)选择受影响对象；API疑问使用knowledge api，运行记录用[logs diagnose](../../log-diagnostics.md)。来源与产物不一致时才继续下述独立重建，不因普通错误自动运行produce或全量验收。按实际故障对象选择对应 Skill。

## 读取当前合同

从工程入口定位实际构建配置、生成器、输入、输出清单和首个失败断言。先读命令的写入位置；名称含test或verify的脚本也可能生成报告或重写交付。记录原始输入与现有输出摘要，使用新输出目录或临时副本验证。

区分源码摘要、规则摘要、产物摘要与测试证据。规则摘要可能仅覆盖业务子集，不能证明完整Lua、素材或GIL字节相同。版本号一致也不能证明来自同一次构建。

## 按证据归因

| 现象 | 核对内容 | 处置 |
| --- | --- | --- |
| 源码摘要不符 | 清单记录的真实输入、当前改动及生成链 | 有意修改则按已授权范围独立重建；非预期变化先定位来源，保留恢复依据 |
| Lua、GIL或资源与清单不符 | 实际正文、生成器输入和最终嵌入内容 | 从同一输入重新生成并回读；不手改清单摘要 |
| 测试证据过期 | 源码、规则、测试、夹具、后端、scope及实际执行用例 | 在当前依赖环境重跑所需检查；旧报告保留历史身份 |
| 工具或模块找不到 | 声明依赖、相对路径基准和随附工具链 | 优先使用显式路径；任务已授权时修复拥有该路径的源码并重新验证 |
| 版本分支不支持 | 工程版本合同与验证器实现 | 判断是配置遗漏还是未实现版本；不删除拒绝分支来放行 |
| 基底或允许范围不符 | 输入摘要、唯一目标、实际修改计划及原生校准 | 修正配置或实现；未知字段保持拒绝，不复制别的工程字段白名单 |
| 独立重建有差异 | 输入闭包、工具版本、路径、时间标签、排序及产物角色 | 定位非确定因素；交付正文逐字节比较，诊断日志按其报告合同处理 |

错误不在表内时，读取断言实现及上下文，不仅按错误字符串猜测。依赖缺失与正文损坏分别报告。

## 修复与重建

诊断、独立重建、正式交付和发布是不同操作。已有任务授权覆盖的源码修复、验证及独立输出重建直接完成；只有真正缺少交付范围或版本决策时才询问。不得因为检查失败而覆盖现有正式输出、修改安装缓存或扩大到冻结对象。

1. 修正拥有问题的源码或配置，避免仅补生成物。
2. 在新目录执行工程声明的制作链，核对实际输入、工具、依赖与产物清单。
3. 回读最终GIL中的Lua、图、信号、资源及挂载，检查预期修改与受保护范围。
4. 执行对应静态、模型和编译回读检查；所需检查不能执行时记录失败或not_checked。
5. 独立重建并比较交付角色；确认输入不变。正式版本和替换操作遵循本次任务授权。

插件统一入口：

```text
python <plugin>/scripts/qianxing.py doctor
python <plugin>/scripts/qianxing.py produce <job.json> --out <new-directory>
python <plugin>/scripts/qianxing.py verify <delivery-directory> --rebuild
python <plugin>/scripts/qianxing.py verify <portable-delivery-directory> --portable
python <plugin>/scripts/qianxing.py capabilities --evidence <checks.json>
```

普通重建可能依赖原位置输入；portable必须有完整随附输入与工具链，并满足声明的外部后端指纹。缺失原始输入、未知原生结构或未实现操作不能通过复制旧报告解决。

## 输出诊断结果

报告首个失败、受影响对象、证据依据、已修复内容、验证结果和剩余事项。静态、Lua模型、原生图模型、编译回读、软件预览、编辑器与实机分别记录；离线通过不能称为宿主通过或用户验收。
