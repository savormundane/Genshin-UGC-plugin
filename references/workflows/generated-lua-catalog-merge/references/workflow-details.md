
# Generated Lua Catalog Merge

## 适用范围

仅用于原神千星奇域制作中的生成Lua目录与对应数据；通用软件、其他引擎的数据合并不触发本技能。

用于把外部 JSON 对照表合并进脚本生成的 Lua 数据文件，例如给资源目录补充分类或标签字段。

适用：

- 外部 JSON 是资料源，Lua 文件由生成器产出且不应手改。
- 生成物参与 `manifest`、规则哈希、发布包或下游检查。
- 新增字段只在部分记录生效，或运行时记录静默消失。
- 生成器正常退出，但 Lua 实际无法加载。

不适用：手写维护的 Lua 文件，或只修改运行时逻辑、不触碰生成物的任务。

## 工作流

### 1. 锁定生成链并证明可重现

先找到生成器、输入JSON、生成物、依赖和下游检查。读取生成器的写入位置，记录输入及现有生成物SHA-256。使用其显式输出参数生成到新目录；不支持独立输出时，在具备完整依赖的临时副本中运行未修改生成器。比较副本输出与原生成物，并确认原始输入、生成器和现有交付未变。不要直接运行会覆盖当前交付的默认命令。

哈希不一致时停止合并，先解释是生成器漂移、输入被手改，还是生成条件不稳定。不要在无法字节重现的基线上叠加新字段。

### 2. 定义 fail-closed 合并契约

- 将外部 JSON 视为只读资料源，不在合并过程中回写。
- 用稳定键（名称、ID）建立映射，并在写入前完成校验。
- 显式声明全量映射或选定子集。全量目录的每条记录都必须有对应条目；子集外记录保持原值。重复键、未知目标键直接报错。
- 开放或必需记录必须解析到允许的分类；缺失或未知分类直接报错，禁止用 `nil` 静默跳过。
- 不可用记录可以显式留空，但必须与“资料表漏项”区分。
- 校验记录总数、开放记录数和分类分布，确认没有部分输出。

校验应发生在生成期，让错误在构建时失败，而不是等运行时才表现为数据消失。

### 3. 只改生成器，不手改生成物

在序列化前按声明的字段合同合并条目。若生成器存在旧记录白名单或按ID过滤的复制循环，应更新拥有该字段的合并规则，或在通用复制后显式赋值；仅限本次声明允许覆盖的字段，不能任意绕过保护字段：

```lua
-- entry.category已经通过映射和允许值校验。
-- category是此次合同明确允许覆盖的字段。
record.category = entry.category
```

序列化字符串键表时，必须输出方括号键。值序列化函数返回的带引号字符串不能直接当键：

```lua
-- 错误：生成器会正常退出，但 Lua 解析失败
Catalog.labels = {"group-a" = "分类A"}

-- 正确
Catalog.labels = {["group-a"] = "分类A"}
```

修改后用生成器在新目录产出生成物，不手工修补生成物。采用稳定顺序序列化，正确转义引号、反斜杠及换行。

### 4. 回读并验证生成物

- 用 Lua VM 或真实下游入口加载生成物，不能只检查生成器退出码。
- 同时抽查低 ID 和高 ID 记录，确认新字段未被旧逻辑过滤。
- 核对记录总数、开放数、缺失数、未知分类数。
- 确认外部输入JSON与原始交付哈希未变；新输出符合声明变化。无实际数据变化的合并允许字节相同。
- 条件允许时，在临时副本中注入缺失或未知映射，确认生成器报错且不写出半成品。

### 5. 跑下游检查并划清交付边界

运行项目现有的内容、规则和发布检查。失败时先归因：

- 生成数据错误：回到生成器修正。
- 下游缓存或构造期状态过期：清理或重建派生状态，或修正接线；不要放宽断言。
- `manifest`/`ruleHash` 过期：这是生成物变更的正常结果，记录当前交付已过期。

已有任务授权覆盖的修复与独立重建直接完成。正式版本与发布范围遵循当前授权；只有确实缺少决策时才询问，不把独立重建自动视为发布。不得为消除告警而手改摘要、覆盖现有发布物或更新冻结变体。

## 常见失败模式

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 新字段只出现在高 ID 记录 | 旧记录白名单/过滤循环跳过字段 | 在循环外显式赋值 |
| 生成器成功，Lua 报 `'}' expected near '='` | 动态字符串键缺少方括号 | 输出 `["key"]=value`，并加载验证 |
| 必需记录从所有分类消失 | 缺失映射被当成 `nil` 静默接受 | 生成期 fail-closed 校验 |
| 检查器读到旧值或旧池 | 构造期缓存、派生状态未清理 | 清理缓存或修正接线，不改生成器迁就 |
| 发布检查报源码过期 | 生成物哈希变化导致清单失配 | 在已授权范围独立重建和验证，正式交付按工程合同执行 |
| 生成器只在部分环境出错 | 输入顺序或序列化不稳定 | 固定输入顺序，重复生成并比对哈希 |

## 完成清单

- [ ] 修改前生成物可字节重现。
- [ ] 缺失、未知、重复映射都会在生成期报错。
- [ ] 新字段在低 ID 和高 ID 记录上都存在。
- [ ] 字符串键表通过 Lua 解析器加载。
- [ ] 原输入和现有交付未改，新输出摘要及实际差异已记录。
- [ ] 下游检查通过，或失败原因已明确归类。
- [ ] 在当前授权范围完成独立重建；正式交付和冻结范围保持正确。

生成目录需要原生素材转换时使用 [GIA无损导入](../../../assets/native-assets.md) 的来源清单；分段源码通过 [有序装配](../../../editor/lua/client-assembly.md) 保留执行顺序、摘要及行号映射。目录别名与游戏专用字段仍由项目提供。
