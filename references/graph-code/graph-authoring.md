# 节点逻辑设计与实际连接

先按[平台接口与工程合同](../workflows/implementation-policy.md)区分自定义接口和已有定义。

## 从行为到图

为每个功能确定：触发事件、权威实体、可读状态、条件、写入、反馈和下一状态。按状态机组织初始化、运行、暂停/取消、结算和重开。每个事件应有可追踪执行入口，查询值的数据线接到实际消费端口；纯数据依赖不代替执行线。

条件分支写清两路，循环明确终止及单帧/事件预算。区分局部、图、实体、全局与持久变量；重开、换局、重连、离场分别定义重置。需定时器时使用真实接口和时间源，防重复启动、迟到事件和已销毁对象访问。

跨端逻辑先由Agent设计新协议表或读取已有表，包含名称、方向、目标、类型/顺序、会话/回合标识、去重和失败。单人原生节点与Lua之间的桥接同样需要合同，不因单人而忽略发送/回包；无需多人系统时不强加房间。

## 节点与类型

查询包内节点库及官方资料选择事件、分支、循环、计算、变量和动作节点，核对图作用域和具体签名。Graph Code是受限DSL；在支持范围内编写完整逻辑并严格编译。编译错误先定位声明、参数和类型，不直接改成空处理或用Lua绕过用户指定的节点图功能。

同类节点的具体泛型、结构体绑定、输入输出类型、变参数量和引脚索引必须一致。自定义信号及结构体相关定义共同扫描编号，核对各通信角色的声明、实例和注册关系。不能只验证连线目标节点存在。

插件维护的值端口合同见 [node-contracts.json](../../scripts/node-contracts.json)。查询和源码检查会核对登记的原文章节及端口。首个合同是 7.1 的「创建实体」，用于确认值输入，并在 Graph Code 中拒绝把它当作值读取。流程端口来自随包编译器定义，原生格式与宿主支持另行验证。添加或调整合同时先从对应版本取证，再运行合法编译和拒绝用例。

## 选择文件路径

- 新图：显式编写Graph Code、项目资源与build.json，严格构建，回读事件、执行/数据连接、类型、常量及变量。
- 既有图修改：按当前样本定位唯一锚点，验证修改前提，生成最小补丁；不为复用新增图命令覆盖原图。
- 当前编译器不支持的结构：依据真实节点/声明编写当前项目适配，保留原结构和未改字段，独立检查输出。缺少可验证结构时才请求最小样本。
- 实体、模板或挂载缺失：有可核验模型时创建并写入引用，分配唯一标识；核对图作用域、宿主类型、入口生命周期和实例依赖，再回读绑定。

统一入口的具体格式见 [节点图构建](node-graph-workflow.md)。工具没有自动挂载命令不免除Agent的挂载实现责任；现有脚本的严格保护规则仍保留。

## 有意义的验证

优先验证实际事件→条件→写入→回包/表现路径及取消、超时、重复、旧包、重开。生成器与校验器不要只共享同一套宽松假设；发现过的声明/索引错误保留结构负例。整合后核对内嵌Lua、图集合、信号、变量、挂载及源摘要。

回读成功证明输出包含所需结构，逻辑模拟覆盖被建模的行为；编辑器能导入和实际平台语义分别验证。无宿主工具时完成其他全部授权工作并交付待复测文件，不因不能自动操作编辑器停在方案。
