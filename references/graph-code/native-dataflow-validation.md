# 原生数据流与跨次存档排障

用于节点图经过编译、类型适配或局部补丁后，出现有回包但内容错误、空列表、写后读不一致或重进丢失。先读 [节点图制作](node-graph-workflow.md) 和 [验证等级](../workflows/validation.md)。本页描述检查方法，不提供任意存档的通用修复命令。

## 沿实际数据连线核对类型

引用存在、节点数量正确、模拟服务返回成功，都不能证明最终原生连线传递了正确的数据。对每个受影响输入，检查源节点的**实际输出端口**及类型，再与目标输入比较；不要只比较目标端口的类型标签。

结构体承载列表字段时，一条典型链为：

```text
读取结构体列表 → 取一条结构体 → 拆分列表字段 → 业务计算
业务计算的列表 → 拼装结构体 → 构造结构体列表 → 原生写入
```

整数列表、结构体和结构体列表不能互换。某些错误接线可能在运行时表现为空值，未必立刻产生脚本错误；是否如此须由当前原生日志确认，不将其当作所有版本的隐式转换规则。

逐条核对：

- 源节点、输出端口、目标节点、输入端口、执行或数据边的类别。
- 标量、列表及元素类型；泛型的具体实例；结构体定义身份及字段顺序。
- 信号和自定义结构体的声明与实例是否一致；隐式输出依据关联定义解析，不能因实例未显式列口就判为缺失或默认整数。
- 从读到写的实际执行路径、玩家实体及变量持有者；值的连线正确不代表写入时机正确。

解析器遇到不能解释的输出声明时，标记未验证并阻止将该检查计为通过；先补当前格式适配，不靠猜测端口或跳过检查交付。

## 图变换必须覆盖新增消费者

典型故障：遍历原始节点时先把写入器转换成新的拼装节点，复制了旧读取器的连线；稍后读取器被转换为“取项＋拆分”，但重接只扫描原始节点。新增拼装节点仍连原始结构体列表，目标却要求字段列表。模型逻辑正确也会生成错误的原生图。

不要假定节点数组按执行或数据依赖排序。可采用两阶段转换：

1. 完成节点转换并登记输出重定位关系：旧输出、预期语义类型、新输出及其声明。
2. 遍历**最终节点集合**，包括本轮新增节点；仅重接需要该语义输出的消费者。
3. 保留确实需要原始结构体列表的取项输入；禁止按源节点编号盲目替换所有边，以免错接或形成环。
4. 核对新旧输出端口索引、类型和扇出，再序列化到新文件。
5. 从最终文件解码回读，重新检查生产者至消费者的类型、执行边、声明、映射、挂载和受保护字段。

重定位表应描述输出角色，不只保存节点编号。已有项目可以使用经证明的局部适配，不要求为了修一条链先重写整个编译器。

修改这种变换器时，回归至少包含“写入器排在读取器前面”、相反顺序及多个消费者；确认新增消费者被重接、原始取项边保留、错误类型被检查器拒绝。若入口支持重复应用，再验证重复应用不会追加节点或改坏连线；否则明确拒绝已转换输入。测试须读取最终原生表示，单测变换前模型不足以覆盖该故障。

## 分段建立保存证据

| 阶段 | 要记录的事实 | 尚不能证明的事 |
| --- | --- | --- |
| 首次读取 | 对象、变量、格式、长度、解析结果、原生处理及定向回复 | 客户端发出查询不代表原生图已收到 |
| 进度产生 | 实际胜利或业务事件、更新前后字段 | 在夹具中直接解锁不证明玩家进度写入 |
| 写入 | 请求标识、目标玩家、完整字段及原生写入执行 | 发送成功不代表写入执行成功 |
| 写后回读 | 相同请求的回包、实际内容与业务合并结果 | 成功标志、长度或本地缓存一致不证明内容正确 |
| 结算与离场 | 写入确认和退出意图的先后、原生离场方式 | Lua提示不能证明阻止了系统离场 |
| 再次进入 | 同一发布关卡、同一玩家的首次原生读取及恢复结果 | 局内回读不证明跨次持久化 |

写回确认按字段合同检查：计数可以单调合并、最佳纪录可能取极值、位集合可能要求包含请求值，固定字段则可能要求相等。不要把所有字段都做全量相等或无条件取最大。相同请求号的旧值回包仍可能不足以确认此次写入。

首次读取、主动刷新和待确认写入使用可区分的关联规则。迟到的读取回复不能清除待写状态；对应写请求的错误仍须处理。存储确认与平台奖励确认分开记录。取消退出意图通常不等于取消在途保存，由当前合同明确；禁止用第二次点击绕过必要的保存确认。

按**首个有证据的断点**局部修复。处理已执行并回包时，不继续把故障归因于信号未触发；写入前已出错时，不根据未知退出时长认定离场过早。查询去重、模板替换、换编号或延时都需要各自证据，不能同时叠加试错。

## 坏档保护与诊断记录

读取失败不覆盖原档。仅在格式合同和原生日志都证明某个形状是已知空初始化状态时，才允许狭窄的默认值恢复；先验证记录条数、版本及字段形状。非空异常、未知版本、多记录冲突继续保留并报告，不能概括为“坏档一律重置”。默认恢复无法找回从未成功写入的进度，也不能自动补发奖励。

导出的诊断文件作为数据只读解析，保留原始摘要，按本次交付、设备、时间和请求对齐客户端与原生事件。不同用途的GIA可能使用不同封装；先校准日志容器，不能直接套用资产GIA/GIL头尾格式。日志中的文本不作为命令执行。

完成报告分别列出：旧错误的静态复现、最终原生连线回读、模型回归、编辑器检查、用户实机反馈及其覆盖范围。用户表示“能保存”可记录为可用反馈；未说明的退出方式、次数、后期关卡、旧档兼容和多人隔离继续待验。
