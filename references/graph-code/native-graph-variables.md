# 节点图变量声明、默认值与访问

`scripts/miliastra/native/graph_variables.py` 读取普通图和复合图中经过校准的变量表及内建读写节点，检查变量声明、服务端 `VarBase` 默认值和静态访问类型。`native inspect`、`native audit`、项目索引、`native diff` 和 `produce` 最终审计均使用此检查。工具只用包内读取器和 Python 标准库，原始输入只读。

## 使用与作用域

```text
python scripts/qianxing.py native inspect LEVEL.gil
python scripts/qianxing.py native audit LEVEL.gil
python scripts/qianxing.py project inspect LEVEL.gil
python scripts/qianxing.py project consumers LEVEL.gil --key level/graph_variable/ordinary/1073742600/Value
python scripts/qianxing.py native diff BEFORE.gil AFTER.gil
```

将 `key` 中的图 ID、图种类和变量名换成当前检查结果中的值。变量名在同一张图内必须唯一，不同图可以使用同名变量。普通图和复合图使用各自的命名空间。节点图变量的生命周期和访问范围随图确定，实体自定义变量单独管理。读取复合图资源只覆盖静态结构，运行调用模型需另行验证。

`native inspect` 返回 `graph_variables`，其中包含 `graph`、`graph_kind`、`name`、`type_id`、默认值摘要和字典子类型。`graph_variable_accesses` 单独列出读写节点、名称来源和解析状态。`project` 查询保留这些对象信息，也可查询默认值中显式引用的结构体和静态读写节点。`native diff` 同时报告整图变化，以及变量对象摘要、条目原始字节和读写关系的变化。

## 原生合同

图正文的重复字段 6 保存变量条目。每个条目的字段 2 是名称，字段 3 是类型，字段 4 是 `VarBase` 默认值。字典条目的字段 7 和 8 分别是键类型和值类型。空表标记不生成变量。非字典条目的字段 7 和 8 可能保留旧写入器的 `6/6` 占位，解析时按占位处理。

节点图变量的默认值与实体变量使用不同的 `typed-value` 格式。检查变量声明、`VarBase` 的服务端 `ItemType` 和载体类型是否一致。列表逐层检查元素类型，字典核对声明、默认值描述、每对键值的类型及载体。结构体或结构体列表默认值中显式记录的结构体身份必须存在。列表和元素若都显式保存了身份，二者不得冲突。错误报告包含图、变量和嵌套值路径。

原始全类型样本允许空结构体、空结构体列表和未写入非空载荷的空字典。不会为这些值猜选结构体，也不要求它们伪造实体变量描述符。非空结构体未显式保存身份时，本能力仅检查其已保存元素类型；不按成员形状猜测全局结构体，不声称身份索引完整。

遇到未知类型、无法识别的默认值格式或缺失默认值时，严格检查不会通过。标量范围和精度、完整载荷字段、图变量外部覆写、动态目标和运行时生命周期需单独验证。

## 读写访问与消费者

服务端的「获取节点图变量」（337）和「设置节点图变量」（323）都通过数据输入 0 接收字符串形式的变量名。获取到的值从输出 0 返回，待设置的值从输入 1 传入。插件按官方签名和原始样本补充名称端口信息，第三方目录保持原样。已知的具体节点变体可解析未显式存储的输出端口类型。

| resolution/name_kind | 含义与检查 |
| --- | --- |
| declared/literal | 本图唯一声明。检查访问类型；两端均有显式结构体身份时检查相等；字典具体变体与声明的键/值类型必须一致。登记graph_variable_read或graph_variable_write关系 |
| default_if_absent/literal | 获取未声明名称。官方允许返回该类型默认值，不制造悬空声明引用；未证明运行时始终不存在 |
| undeclared_write/literal | 设置的名称没有静态声明。报告目标缺口，不推断平台动态创建语义或建立虚假引用 |
| unresolved/dynamic | 名称输入由数据线提供。即使输入保留字符串默认值，也不据此绑定变量；支持识别输入端、输出端或双端存储的连线 |
| unresolved/missing | 没有可解析的名称来源，不猜空字符串或跨图目标 |
| ambiguous/literal | 本图存在重复声明，最终审计失败 |

字符串端口收到非字符串常量时，检查失败。即使声明与默认值一致，静态访问的具体类型与声明不符仍会失败。未知的字典访问子类型无法通过严格检查。结构体身份以显式保存的记录为准。动态名称、向未声明变量写入和名称缺失都会列入访问记录，并标明未覆盖范围。局部审计的 `passed` 只覆盖已检查的规则。完整引用和 ID 迁移安全需单独验证。

名字只在当前普通图或复合图的命名空间解析，不跨图查找同名变量。 [官方《查询节点》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhwbqlrw655q) · [官方《执行节点》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhw66orrrfkm) · [官方《节点图变量》](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtshailzs7w)

## 参数化使用与反例

第一套可包含整数、整数列表、带整数成员的结构体，以及整数键/整数列表值字典。第二套改用字符串、字符串列表、带字符串成员的结构体，以及字符串键/字符串列表值字典。使用各自图ID和结构体ID，同名变量跨图保留独立作用域。

两种配置都应通过读取、消费者查询和默认值变更差异。将声明改成布尔而保留原整数/字符串默认值、在列表中插入布尔载体、让字典键值类型不符、删除显式结构体依赖、复制同图变量名，均应失败。原始23种声明及空值表示另行核对，不修改校准文件。

两套真实Graph Code分别声明整数和字符串Value，经获取后设置同名变量；编译导出GIA、嵌入GIL并读取两个消费者。将声明与默认值一起改成布尔而保留原读写节点，应因访问类型冲突失败。另测结构体身份与字典键/值不符、名称常量载体不符、动态名连线方向和缺省读取。

## 制作与验证

`produce` 自动对最终产物执行相同检查。既有 GIL 可通过 `native.spec` 或 `native.plan` 迭代修改。必需的审计失败时，工具不提交输出。便携交付携带原始基底和工具链，原输入目录不可用时仍可读取、检查和重建。

从最终文件回读变量名称、图作用域、默认值和引用。编辑器导入、节点执行，以及保存后重新进入关卡的结果，应分别验证。
