# 点阵像素图处理与导入指南

> 适用范围：把任意 PNG 立绘 / 封面 / 图标变成千星奇域 Lua 脚本可渲染的色块数据。
> 本文介绍动画立绘与静态封面的通用处理方法。
> 历史制作观察用于方法参考；当前项目仍须独立验证。下文尺寸和预算仅用于示例，不表示特定作品或平台限制。

---

## 一、为什么必须离线编译成色块

千星沙箱的硬约束决定了图片素材**只能走「离线编译 → 色块矩形 → 控件池」这一条路**：

| 沙箱约束 | 影响 |
| --- | --- |
| 不能导入自定义图片 | PNG 无法作为图片控件素材，运行时也读不了本地文件 |
| 没有 `require` / `io.*` | 编译必须在沙箱外完成，数据以 Lua 表内联进单文件脚本 |
| `Paint → Ink` 画小块实机显示为胶囊圆角 | 想要直角色块轮廓必须用单图片控件模板 |
| 模板索引是存档内局部值 | 换存档必须重新确认可实例化的图片控件模板索引 |
| 单组控件上限（软 700 / 硬 900，实测可超） | 大图色块数必须控制在可接受范围，或明确豁免预算 |
| 画布坐标原点左下角、有父控件时 `SetAnchoredPosition` 相对父级中心 | 渲染层必须做坐标变换，见 §五 |
| `ColorValue` 字节序 `0xAARRGGBB` | 颜色一律用 `Color(r,g,b,a)` 构造，不要手拼整数 |

**结论**：一张图的全部信息被压缩成两份 Lua 数据——**调色板**（`{r,g,b,a}` 列表）+ **矩形列表**（`{x,y,w,h,paletteIndex}`），每个矩形对应实机上恰好一个图片控件。

## 二、处理流水线总览

```
原始 PNG（任意分辨率 RGBA）
      ↓  1. alpha 阈值化（harden）
      ↓  2. 预乘 BOX 降采样（normalize）
      ↓  3. 中位切色（median-cut ≤96 色 + 强制保留强调色）
      ↓  4. 逐像素归类 → 水平行程 + 精确纵向合并（初始矩形）
      ↓  5. 贪心边界盒合并（Merger，可镂刻 carve）
      ↓  6. 生成紧凑调色板 + Lua 数据 + lupa Lua5.3 校验
      ↓  7. QA 对比图 + JSON 报告
static_image.lua / animation_frames.lua
      ↓  内联进单文件 Lua
控件池渲染（§五）
```

按上述步骤实现离线编译；包内独立转换入口见末尾工具索引。

### 2.1 alpha 阈值化（harden）

- 原图常带成千上万个近透明彩色残影像素，直接编译会出现脏边。
- 规则：`a >= 阈值 → 全不透明(255)`，否则 `(0,0,0,0)`。
  - 立绘动画类（角色）：`ALPHA_MIN = 128`，牺牲柔边换干净轮廓。
  - 不透明封面类（静态封面）：`ALPHA_MIN = 96`，图本身全实，只是清边缘锯齿。
- **降采样之后要再做一次阈值化**：预乘 BOX 下采样会在边缘产生中间 alpha，不二次阈值就会残留灰边。

### 2.2 降采样（normalize）

- **必须预乘**：`convert("RGBa").resize(..., BOX).convert("RGBA")`，防止透明像素的 RGB 渗进保留色块。
- 步长按目标控件预算反推：

| 案例 | 原图 | 降采样 | 网格 | 控件预算 |
| --- | --- | --- | --- | --- |
| 动画单帧 | 320×320 | 2× | 160×160 | ≤1500 块/帧 |
| 静态封面 | 1440×1080 | 8× | 180×135 | 2600 块（静态封面） |

- 经验：**网格越大细节越好，但初始矩形数暴涨**。先 `--probe` 看初始矩形数，再决定步长与目标块数。

### 2.3 调色板量化（≤96 色）

- Pillow median-cut 在真实前景像素（`a>=96`）上取色，不是粗糙 posterize。
- **强制保留强调色**：median-cut 容易糊掉的特征单独挑出来塞回调色板，并删除与之最接近的冗余色对：
  - 深色线条 / 眼睛墨色（`max(c) < 90`）
  - 纯白高光（`min(c) >= 240`）
  - 亮发色（`r>=240, g>=225, b<200`）
- 调色板**逐帧独立**（动画各帧各自一份紧凑表，只含该帧实际用到的颜色）。

### 2.4 初始矩形：行程 + 纵向合并

1. 每个像素归类到 `(调色板序号, alpha档位)` 键。
2. 每行相同键的水平连续段为一个「行程」。
3. 相邻行同 x 跨度同键的行程精确纵向合并。
- 4 档 alpha（255/192/128/64）：立绘保留半透明边缘层次；全不透明素材可直接单档 255。

### 2.5 贪心合并（Merger，压块数的核心）

- 候选 = 两个相触矩形的联合边界盒；盒内必须全是前景且 ≤ `MAX_MERGE_AREA`（400 px）。
- 全含的矩形吸收；部分覆盖的邻居在允许 carve 阶段被镂刻（盒内部分吸收、盒外保留原色）。
- 排序键：`新增误差 / 减少的矩形数`；误差 = 不透明加权 RGB SSE + 2× alpha SSE。
- 局部对比度权重 `1 + 6*contrast` 让高光、线条、轮廓像素难被合并，保细节。
- 先做无损失几何吸收（phase 1），无候选可并时再开 carve（phase 2）。
- **产物矩形互不重叠、永不覆盖透明像素**（`verify()` 逐像素断言）。

### 2.6 输出与校验

- Lua 文本生成后必须用 **lupa.lua53** 实际执行一遍：核对帧数、池大小、每条 rect 边界 `x+w<=w, y+h<=h`、调色板索引 1-based 有效。
- QA 对比图：源图 vs 编译结果，同底色（棋盘格 / 深绿）并排 ×3 放大 + MAE / IoU 指标。
- JSON 报告：记录源文件 SHA-256（换图时先核对是不是同一批素材）、编译参数、质量指标。

## 三、Lua 数据格式（两案统一）

```lua
local DATA = {
    pixelScale = 0.380,        -- 每格多少设计单位
    maxRects   = 1500,         -- 控件池大小 = 各帧最大矩形数
    -- 动画才有：flightOrder = {1,2,3,2},
    palette = { {r,g,b,a}, ... },          -- 1-based
    rects   = { {x,y,w,h,paletteIndex}, ... },  -- 帧内网格坐标
}
return DATA
```

- 动画用 `frames = { {name, w, h, anchorX, anchorY, palette, rects}, ... }` 包一层。
- **锚点**：动画帧要有公共参考点（可选稳定的局部特征点），否则切帧时脸会跳位；镜像围绕每帧自己的 `anchorX`，不能用画布中心。
- 静态封面把锚点换成整数居中 letterbox：`sx=(画布W - w*ps)/2, sy=(画布H - h*ps)/2`。

## 四、编译参数速查

| 参数 | 动画立绘（动画立绘） | 静态封面（静态大图） |
| --- | --- | --- |
| 降采样步长 | 2 | 8 |
| alpha 阈值 | 128（二次阈值化） | 96（二次阈值化） |
| RGB 色数上限 | 96 | 96 |
| alpha 档位 | 255/192/128/64 | 全 255 |
| 目标块数 | 1500/帧 ×4 帧 | 2600 |
| pixelScale | 0.380 设计单位/格 | 6.6667（=1200/180） |
| 坐标含义 | 帧 160×160 网格 | 画布 1200×864 整数居中 |
| 质量 | 前景 MAE ≈ 11–13 | 全图 MAE ≈ 7.8，IoU 1.0 |

**预算参考**：战斗内常驻 UI 遵守软 700 / 硬 900；封面、过场等可独占场景的大图按「实测能跑 + 有回退」自定预算（封面 2600 块实测可行）。预算紧张时优先增大降采样步长而不是砍调色板。

## 五、控件池渲染适配（Lua 侧）

运行时实现要点：

### 5.1 建池

- 只建**一套**池，大小 = 各帧最大矩形数（角色 1500），不是每帧一套。
- 在隐藏父容器下创建；`OnStart` 建 180 个，之后每次 `OnUpdate` 补 180 个，全池就绪才显示完整图。
- 不可点击的色块尽量 `raycastTarget = false`。
- 模板索引用**当前存档确认**的直角图片控件模板，不要沿用旧存档的 `1073741857`。

### 5.2 切帧只改已有控件

```lua
-- 帧内网格坐标 -> 屏幕位置（相对父容器中心）
dx = x + w/2 - anchorX          -- 面左时 dx = -dx
cx = dx * ps                    -- ps = pixelScale * view.scale * magnification
cy = (anchorY - y - h/2) * ps   -- Y 翻转：网格 y 向下，画布 y 向上
块位置 = SetAnchoredPosition(cx, cy)
块尺寸 = SetSizeDelta(w*ps, h*ps)
块颜色 = imageColor = Color(palette[i][1], [2], [3], [4])
```

- 只在 **帧 / 朝向 / 缩放** 变化时重写；移动角色只挪父容器。
- 切到矩形更少的帧时，把尾部多余控件 `SetVisible(false)`。
- 每帧缓存每块的 `(cx, cy, w, h, colorKey)`，未变化的块跳过 API 调用。

### 5.3 生命周期与层级

- 销毁只销毁父容器，让子块跟着回收（逐个销毁会被引擎拒绝并刷警告）。
- 暂停 / 弹窗复用同一池（如复用第 4 帧待机），只改父容器尺寸位置，不建第二套。
- 层级顺序：背景 Paint → 角色根 → HUD/弹窗 → 全屏输入；用 `SetAsLastSibling` 重排**父容器**，不要每帧重排上千块。
- 失败回退：任何一步建池 / 切帧失败，置 `failed` 标志，退回旧色块画法，不要一边持旧池一边重复分配。

### 5.4 动作选择（以主角为例）

- 某类跟随逻辑用 `abs(vx)>15 or not onGround` 判飞行；**当前角色若始终浮空，直接照抄会导致永不待机**——改用自己的移动意图 / 空中状态判定。
- 飞行循环 `1→2→3→2`，7 fps，用 `OnUpdate(dt)` 累积时钟切步，不用 `rAF`。
- 四帧数据**没有**攻击 / 受击 / 落地帧，需要时新做素材另编译，不能拿现有帧冒充。

## 六、踩坑清单（实机验证）

| 坑 | 正确做法 |
| --- | --- |
| 对降采样派生图重复「无损」编译 | 派生图已经丢掉柔边信息，要改画质必须回原 PNG 重编；找不到原图就接受现有质量 |
| 模板索引跨存档复用 | 每个存档先小规模试建，确认可实例化再建大池 |
| Paint→Ink 画色块 | 实机显示胶囊圆角，轮廓类素材必须用直角图片控件模板 |
| 切帧销毁重建上千控件 | 严重卡顿；永远只改已有控件 |
| 镜像用画布中心 | 光环 / 脸会左右跳；必须按每帧 anchorX 翻转局部 x |
| 用 `%d` 格式化画布尺寸 | 画布可能是小数，报 `number has no integer representation`；用 `tostring` / `%.1f` |
| 手拼 `0xAARRGGBB` 颜色整数 | 字节序易错；一律 `Color(r,g,b,a)` |
| 池隐藏用 `SetActive(false)` | 会停脚本逻辑；隐藏必须 `SetVisible` |
| 「能看到 PNG」≠「能导入沙箱」 | 沙箱运行时不读本地文件，交付物只有编译后的 Lua 数据 |
| 贪心合并后出现重叠 / 盖住透明像素 | 编译器必须带 `verify()`：逐像素断言矩形恰好铺满 `alpha>=阈值` 集合 |

## 七、包内工具与使用

独立转换脚本为 [pixel_to_lua.py](../scripts/pixel_to_lua.py)，依赖 Python 和 Pillow。从技能根目录运行，使用当前项目原图和新的输出目录：

```powershell
python scripts/pixel_to_lua.py SOURCE.png --out NEW_DIRECTORY --step 2 --colors 32 --alpha-min 128 --max-rects 1500
```

脚本输出 data.lua、report.json 和 preview.png。它实现精确矩形合并，没有实现指南中的有损贪心融合；超过预算会拒绝写入。先检查预览、矩形覆盖与透明边缘，再内联数据并配置当前存档的模板。帧播放方法见包内点阵运行时参考。
