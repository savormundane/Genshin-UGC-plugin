# 平台更新、兼容与恢复

四个 Skill 入口为 Qianxing Editor、Qianxing Graph Code、Qianxing GIL 和 Qianxing Assets。Client Lua 由 Qianxing Editor 提供。入口只维护触发与领域约束；共享事实由原始资料和对应指南单点维护。原始API、官方镜像、校准、许可证和第三方目录保留。历史经验只有经核对的通用结论进入当前规则；完整游戏和专属协议不进入能力登记。

## 来源更新

区分插件版本、目标平台版本／模式、文档来源版本、合同schema和后端版本。文档版本未知时保持空值；获取时间不是官方更新时间。资料继承保留requested_version、source_version、inherited。

1. 用已配置Python运行 `qianxing.py knowledge snapshot`，保存JSON到新的开发证据文件；该命令只输出数据。
2. 按需取得新资料到独立位置，对照原文；平台正文使用 `docs diff --from VERSION --to VERSION`。不默认联网爬取。
3. 审查签名、权限、生命周期、适用模式和行为约束。文档冲突同时保留依据；新文档不自动覆盖已确认的不同运行环境。
4. 有依据才更新原文、来源目录和摘要。路径迁移或链接更新与语义变化分别登记，不仅重钉摘要制造通过。
5. 再保存snapshot，用 `knowledge diff BEFORE.json AFTER.json` 列出来源及API合同变化、受影响能力和建议专项。结果是审查辅助，未执行任何测试；API删除或变化需兼容审查，正文未变不能证明宿主版本兼容。
6. 按建议和实际源码依赖执行定向回归。无法判断语义影响时扩大检查范围；普通说明改动只核对结构与链接。

## 合同与迁移

CLI与MCP使用同一实现。已有schema 1/2及旧线上协议语义保留，未知版本拒绝，不静默改默认值。新增字段兼容读取；改变含义或必填字段需新schema／显式平台选择。旧日志、旧工作流owner保持可读，迁移结果输出新文件及差异。

plan保持旧输入参数，routing_schema=2 标明主入口；support是候选而非必经阶段。旧十个工作流owner通过稳定登记解析，不依赖Skill目录扫描；原配置及历史证据不改写。旧Skill显式调用需使用[迁移映射](skill-map.md)。

GIL与存档只有明确校准和字段合同才能迁移；旧档、未知版本及异常记录不覆盖。工具回退不能自动逆转已提交的游戏数据。

## 发布、安装与恢复

实施期间执行相关专项；版本与文件确定后集中验收一次，失败仅重跑受影响项。报告保存输入、工具、规则、后端及用例身份；静态、模型、编译回读、软件预览、编辑器、宿主和用户验收不互相替代。

使用新版本目录安装；先保存上一稳定源码／包、逐文件摘要、依赖锁及运行配置，再通过宿主支持的安装流程切换。新安装核对清单、文件摘要、专用解释器和stdio实际调用；涉及Beyond时运行中性场景。Codex工具发现与游戏宿主另记，不能用stdio代替。

安装器可能自动清理旧缓存，不能把缓存当作唯一回退副本。通过保存的源码／包重新安装旧版本并恢复匹配环境绑定；不原地拼接缓存。原有环境未经依赖变更无需重建，版本目录名不代表解释器必须复制。回退执行仍遵循当前任务授权。
