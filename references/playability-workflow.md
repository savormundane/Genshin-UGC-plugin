# 千星奇域体验制作与游玩检查

## 操作与反馈闭环

先明确玩家主要操作、反馈、目标、失败/取消、结算和重开路径，再决定节点图、客户端Lua、原生实体与多人协议的分工。新玩法先贯通进入→首个操作→状态推进→结果→重开，再扩充内容。成熟玩法只做目标增量，不为流程重写。

将操作写成可观察条件：输入是否被接受、状态如何改变、玩家看到什么反馈、何时能再次操作。胜败和重开不能只存在于界面。动作类优先辨认场景与危险；棋盘/菜单类允许核心交互占主要区域，按实际玩法决定界面密度，不套统一HUD比例。

## 规则、表现与输入分工

规则状态拥有回合、计时、胜败及可保存数据，表现层根据状态更新控件、动画与提示。单客户端玩法可由Lua拥有规则；需要服务端权威/原生实体的玩法由真实节点图和协议推进，不能把动画结束或控件显隐当权威结算。

按玩家意图集中映射确认、取消、选择、移动和技能等输入，使用实际支持的API。菜单/弹窗打开、隐藏、切页、重开及销毁时处理命中、监听、计时和按住状态；需要屏蔽移动/镜头时读取真实接口并验证，不虚构全局输入锁。重复点击、旧事件和延迟回调不能重复结算。存档保存规则数据，不保存控件实例。

键鼠调用同一动作入口；按住键、等待回包、弹窗关闭及切页后不能额外触发。确认提示、禁用状态和实际键位一致，平台原生退出另验。共用逻辑变更时检查所有受影响的可达入口，按需比较交互体验与模型结果。可选的多人恢复、权限及玩法核验见[历史案例](production-experience.md)。

## 界面与目标设备

进入后能找到首个操作；信息按当前决策需要显示，说明与低频设置可折叠。关键信息在动画和场景变化下仍可读，反馈不长期遮挡主要操作区域。PC和手机分别检查尺寸、触控命中、拖动/镜头冲突、弹窗遮挡与关闭恢复；只声明实际检查过的设备。不要把网页DOM表现当宿主控件验证。

## 素材与动作一致性

确定一份角色/图标基准，保持轮廓、调色板、比例和朝向规则。动作帧使用公共画布、统一缩放及共同锚点；不逐帧独立自动裁切再拉伸到同尺寸。AI生成动作时优先在同一参考下生成完整序列，需要实际生成时使用可用图像能力；本流程不新增图像服务或复制外部素材脚本。

经内置素材入口处理透明边缘、预算、矩形/富文本和Lua数据；动画能力负责播放、镜像与控件池。检查静止、切帧、镜像、切动作和重开后的锚点及占用。离线预览用于发现问题，宿主实际尺寸、裁剪、色彩和负载另验。

## 沿玩家路径检查

```text
python scripts/qianxing.py workflow playtest --device both
python scripts/qianxing.py workflow playtest --device mobile --multiplayer --persistence
python scripts/qianxing.py workflow playtest --report PLAYTEST.json
```

第一条生成基础检查矩阵，包含进入、主操作、反馈、结算、重开、菜单输入、界面、素材及预算；选项增加多人进入/旧包/恢复，以及读档失败/写入确认/同一发布关卡退出重进。矩阵是待执行清单，不是已完成报告。

按目标文件和设备分别记录。先运行可用的静态/逻辑模拟；编辑器和实机按实际条件执行或明确待验，不要求OCR、截图识别或鼠标键盘自动操作。UI问题和规则问题分别定位，不用源码正确替代视觉与交互检查。

报告格式如下；path相对报告文件，sha256填写实际文件摘要。此示例仅说明结构，不能直接作为验收证据：

```json
{
  "schema": 1,
  "domain": "genshin-qianxing-ugc",
  "artifact": {"path": "level.gil", "sha256": "实际64位小写摘要"},
  "device": "mobile",
  "cases": [{
    "id": "restart", "status": "not_checked", "layer": "host",
    "expected": "重开后首个输入有效且计时重置", "reason": "等待目标设备复测"
  }],
  "issues": []
}
```

已执行的case使用passed/failed，填写非空steps列表、expected、actual及evidence列表。每个evidence为path、sha256、layer；layer为static/simulation/editor/host并须与case一致。待验用not_checked，确实不适用用not_applicable，均填写具体reason。报告覆盖本轮相关路径，不能通过省略失败或待验项声称全部通过。

问题包含id、severity（P0/P1/P2/P3）、case（对应检查ID）、subsystem（rules/input/ui/assets/network/persistence/packaging）、steps、expected、actual。按影响优先处理：P0导致无法进入/数据损坏，P1阻断核心流程，P2局部错误，P3轻微表现问题。失败case或P0/P1令命令退出1；无效/过期报告退出2。问题修复后对新文件重新执行受影响路径，不能复用旧包摘要。

检查器只验证报告结构、关联文件摘要和证据层级，列出失败、待验及阻断问题；不会运行游戏、证明手写证据真实、自动确认玩法语义或实机完成。无阻断也不等于验收通过，尤其仍有pending_cases时。当前任务只需有意义的检查，不强制为单点修改跑完整玩法清单。
