# 08 · 踩坑清单

按"**出问题时先查这里**"的用法组织。每条：现象 → 根因 → 修法 → 怎么发现的。

> **现象和根因是客观的**（换了实现方式也可能踩到）；**"修法"是我们当时的解法**，
> 可以换成别的，只要解决同一个根因。有些坑还写了"教训"，那部分比具体解法更值得记。

---

## 坑 1 · 整个角色窜到窗口右上角

- **现象**：图元都建出来了，但全挤在画面右上角，看不出形状。
- **根因**：`game.GetCursorUIPos()` / 画布空间用的是**左下原点**，
  而控件 `SetAnchoredPosition` 用的是**容器中心原点**，两者相差半个画布。
  直接把画布坐标喂给 `anchoredPosition` 就整体偏了 (+W/2, +H/2)。
- **修法**：位置计算末尾减去 `CX, CY`（`CX/CY` 运行时用 `game.GetUICanvasSize()` 取）。
- **量化**：修复前 X∈[620, 950]、Y∈[155, 740]（全在半画布外），
  修复后 X∈[-180, 150]、Y∈[-297, 293]。**用数值验证，比看图可靠。**
- **发现**：用户反馈"全都在窗口是右上角点能看出形状"。

## 坑 2 · 脚本一帧都不跑

- **现象**：脚本加载了、没报错，但什么都没发生。
- **根因**：脚本的逐帧回调**默认关闭**，不显式打开 `OnUpdate` 一次都不会被调用。
- **修法**：`OnStart` 里 `script:EnableUpdate(true)`（旧运行时回退 `EnableTick`）。
- **发现**：用户反馈"问题还是在忘记开 EnableUpdate 了"。**这条只能靠真机发现。**

---

## 坑 3 · UI 一个都建不出来、快捷键一起失效

- **现象**：日志只有一句"UI 未建"；按钮、文字、拖动条、快捷键全都没有。
- **根因**：`OnStart` 里容器还没解析出来（`root == nil`）就调 `UIBuild()`，
  而 `InstantiateClientUIControl(prefab, nil)` 是**静默失败**（返回 nil，不报错）。
  按键监听是挂在控件上的，控件没建出来 → 监听 0 个。
- **修法**：先 `ensureRoot()` 确认容器；失败就留给 `OnUpdate` 每帧重试到就绪。
- **量化**：修复前 UI 控件 **0** 个 / 按键 **0** 个 → 修复后 **92** / **16**。
- **发现**：别人拿去做实机测试时发现。**我原来的测试桩没抓到，因为桩里的
  `InstantiateClientUIControl` 没校验父节点，把 nil 吞了** ——
  桩比真实 API 宽松，就会漏掉这类 bug。

---

## 坑 4 · 腰部撕开一条缝（4.2px）

- **现象**：身体转的时候，腰/脖子处出现错位裂缝。
- **根因**：给**相邻部件不同的变换权重**（身体转 1.6°、腿只转 0.48°，
  200px 力臂上就是 4px 的位移差）。
- **修法**：改用**连续位移场** `Δ = F(x,y)`。相邻图元拿到的位移只差一点点，
  部件边界这个概念在算法里直接消失。
- **发现**：视觉检查 + 数值复核（算法改后相邻 2px 采样的最大跳变 0.0535px，
  旧方案是 0~4.2px 的台阶）。

---

## 坑 5 · 脚在地上滑 / 大腿跟着身体平移 7px

- **现象**：视点跟随时脚会动，或大腿整体平移。
- **根因**：躯干斜坡的"0 点"放在了**脚底**，于是脚底以上全都在动（大腿平移 7px）。
- **修法**：斜坡起点放在**髋线**（腿部件组的 y 上沿）。髋线以下 `s(y)=0`，
  腿脚**自动**钉住，不需要在算法里特判腿。
- **量化**：修前脚水平 6.96px，修后 **0.00px**。

---

## 坑 6 · 整颗头在横滑（像"漂浮木偶"）

- **现象**：鼠标一动，头整体平移，很假。
- **根因**：两处叠加——① 头部有整体平移（`GAZE.dx = 7px`）；
  ② 躯干场在脖子以上仍保持满幅，头又吃了一遍。
- **修法**：① 头部**不做整体平移**（方向感只由柱面形变提供）；
  ② 躯干斜坡加**第三段**：脖子 → 头顶从 1 衰减到 `headKeep`(0.25)，**让脖子吸收掉大部分转角**。
- **量化**：头水平位移 21.55px → 17.29px，且是"形变 + 小幅跟随"而不是纯滑动。

---

## 坑 7 · 眼白不眨眼 / 眨眼后眼睛没恢复

- **现象**：眨眼时只有虹膜在动；或眨完之后眼睛一直是细长的、alpha 也没还原。
- **根因**（三个独立 bug）：
  1. 生成器写的 role 是 `eye`，Lua 里判断的是 `sclera` —— 名字不一致
  2. 尺寸只在 `nh ≠ s.h` 时写回，压缩后又恢复时恰好相等 → 该写的时候没写
  3. 淡出/还原的标志位写进了**逐图元循环**，被第一个图元清掉了
- **修法**：名字逐字对齐；**带 role 的部件每帧都写尺寸**；淡出判定按**部件**做一次。
- **量化**：现在 681 个控件压缩、681 个 alpha 降、681 个 alpha 还原。
- **发现**：真 Lua 运行时（lupa）实跑才发现的 —— 光看代码看不出来。

## 坑 8 · 切预设之后旧通道还在生效

- **现象**："说话 → 全停"之后，说话通道的值还是 1。
- **根因**：每帧重算通道值时**遍历了 `CFG.ch`**，而切预设时把 `CFG.ch` 换成了空表 ——
  遍历等于什么都没做，`chv` 里的旧值就挂在那儿。
- **修法**：遍历**固定的 `CHANNELS` 清单**，没写到的通道一律归零。

---

## 坑 9 · 拖动条/按钮在实机不跟手

- **现象**：预览里好好的，进游戏拖不动或跳变。
- **根因**：光标事件回调的签名文档**没写死**，可能传 `(cursorEventData)`、
  `(control, data)`、`(x, y)` 甚至什么都不传。
- **修法**：做成**签名无关**——遍历参数，认出 `CursorEventData`（有 `GetUIPos`）就用它，
  有两个数字就用数字，都没有就退回 `game.GetCursorUIPos()` 轮询。
  并在日志里打印**实际用的是哪条路径**。
- **同类**：按键监听挂在哪个控件上能收到也不确定 → **多路兜底**（先试容器根节点，
  再试角落命中区），日志写明绑在哪一路。

## 坑 10 · 找不到容器却静默空转

- **现象**：进游戏"脚本没反应"，什么日志都没有。
- **根因**：找不到容器时每帧空转，而错误只落在 `ErrorLog.txt` 里。
- **修法**：连续 60 帧找不到容器就**停掉逐帧回调**并打印原因，
  绝不做"每帧空转又什么都不显示"的哑巴脚本。

---

## 坑 11 · 层序静默错乱

- **现象**：偶尔有图元被盖住/浮到不该在的层。
- **根因**：`SetSiblingIndex` **会返回 boolean 且"受父控件子控件数量限制"**，
  失败时返回 false，但很多人不检查返回值。
- **修法**：检查返回值为 false 就 `warnOnce` 出声；层序不依赖目录/遍历顺序；
  有 UI 时角色铺完统一按「背景 → 角色 → UI」重排。

---

## 坑 12 · 白描边（最绕的一个）

- **现象**：轮廓外侧一圈 1~3px 的浅色描边，深色背景上特别明显。
- **排查过程（走过一次弯路）**：
  1. 先量几何：外溢只有 0.68%（10030 个里 90 个）→ **否掉"图元画到外面了"**
  2. 再量颜色：环带偏亮，但结论一度是"重建偏暗" —— **因为我拿预乘 alpha 的颜色直接比了**
  3. 反预乘后重测：**1px 环 57.8% 的像素偏亮、均值 +6.45** → 确认是颜色问题
  4. 追根因：原图透明区是纯白 + Lanczos 放大不做预乘 → 白色卷进边缘 → 拟合器照着取样
- **修法**：数据级三步（剔溢出 / 缩回轮廓 / 轮廓改色），**不按颜色删图元**。
  上游再加一步"放大前把透明区染成邻居颜色"。
- **量化**：最外环"明显偏亮(>25)"像素 1568 → **82**；内部 RMSE 22.40 → 22.23（没伤里面）。
- **教训**：
  - **颜色比较前先反预乘**（否则结论会反）
  - **不能按颜色删图元**：花朵、衣服金边、瞳孔高光本来就有大片近白像素
  - 显示层遮罩只能当诊断，**Lua 侧没有 stencil 掩膜**，别依赖它

## 坑 13 · 跳跃落地后停在半空

- **现象**：跳跃动画结束，角色停在空中或保持半蹲。
- **根因**：写入缓存（位移小于阈值就不调 API）把**恢复那一帧的小位移吃掉了**。
- **修法**：恢复帧把阈值压到 **0**，强制精确写回原位。
- **同类**：跳跃位移必须施加在**表情之后**，否则眨眼时眼球留在原地、脸飞上去。

---

## 坑 14 · 逐动作排查时"动作在播但什么都没动"

- **现象**：`GetStatus()` 显示有动作在播，但角色没反应。
- **根因**：一个动作可以"在播却什么都不动"（通道被开关挡住、或被新加的骨骼分支提前 return）。
  只检查"在播"是不够的。
- **修法**：写**逐动作位移量测**（每个动作单独跑一遍，量代表图元的位移峰值，与基线比）。
  本项目用它证明"加了跳跃之后其它 13 个动作没被改坏"。

## 元教训（比单个坑更值钱）

1. **桩比真实 API 宽松，就会漏掉 bug**（坑 3）。测试桩要尽量"严格"：
   该失败的失败、该校验的校验。
2. **能量化的就别靠眼睛**（坑 1、4、7、12）。位移范围、写入次数、环带亮度——
   数字能定位到具体哪一环错了。
3. **坐标/单位/参考系**是这类项目最大的 bug 来源（坑 1、5、6、7）：
   弧度 vs 度、半径 vs 直径、0-based vs 1-based、左下原点 vs 中心原点。
   **每写一段涉及坐标的代码，先问自己现在是哪套。**
4. **静默失败最贵**（坑 3、10、11）。凡是"返回值可能是 nil/false"的 API 调用，
   都要检查并出声。
5. **只有真机才知道的事**（坑 2、3、9）：忘开逐帧回调、容器就绪时序、回调签名。
   预览再像也不能替代一次真机跑。
