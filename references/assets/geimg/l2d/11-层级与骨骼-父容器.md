# 11 · 层级与骨骼：用「父容器」代替逐图元写入

**这是目前我们量到降负载幅度最大的一条路（比补间更彻底）。**

一句话：**同一骨骼的图元挂在一个父容器下，只对父容器做动画** ——
那么每帧要写的就不是近万个图元，而是几十个容器。

---

## 11.1 为什么成立（API 依据）

| 依据 | 出处 |
|---|---|
| `ClientUIBaseControl.parent` 是**读写**字段 | 基类字段表 |
| `game.InstantiateClientUIControl(uiPrefabId, parent)` **创建时就能指定父级** | game 函数表 |
| API 里有专门的 **`ClientUIContainerControl`（容器节点，"用于组织子控件"）** | 控件类型表 |
| 官方规范原文：**「父子层级中的位移、缩放、显隐、Alpha、镜像与裁剪效果由运行时 UI 层级共同决定」** | PDF 文字层（未裁切的正文） |
| 子控件查询：`GetChildren()` / `GetChild(name)` / `FindChild(path)` | 基类方法表 |

也就是说：父控件的变换会**作用到子控件**，这正是"骨骼"的机制。我们不需要引擎给我们一套骨骼系统，
**用控件层级就能搭出来**。

---

## 11.2 架构：容器即骨骼

```
root（GEIMG_Canvas 容器）
 ├─ 部件容器 × 26           ← 每帧主要写这些
 │   ├─ 图元控件（该部件的全部图元，一次性创建、之后不再动）
 │   └─ 子骨骼容器（可选，用来做弯曲/甩动）
 │       └─ 图元控件
 └─ UI 层（背景/按钮/文字）
```

**映射关系**（把现有的动作系统平移过来）：

| 现有做法 | 层级化之后 |
|---|---|
| 每个图元的 `anchoredPosition` 逐帧写 | **图元不再写**；写它所属的容器 |
| 呼吸 = 每个部件算 dy/rot 再逐图元施加 | 部件容器直接 `anchoredPositionY` / `localRotationZ` |
| 摆臂 = 手臂部件的图元绕肩旋转 | 手臂容器**放在肩点**上，转容器即可 |
| 甩发 = 按"离轴距离"逐图元加转角 | 头发拆成 **发根 / 发中 / 发梢 三个子容器**，各自转一点 → 天然的鞭状 |
| 眨眼 = 335 个眼图元的 `sizeDelta` + alpha | **眼容器** `localScaleY` 压一下（1 次写入）+ 眼睑容器下移（1 次） |
| 跳跃 = 逐图元算 jHip/jKnee 权重 | 躯干/大腿/小腿各一个容器转一点（≈6 次写入）；根容器一条位移 |
| 视点：虹膜滑动 | 虹膜容器 1 次位移 |
| 视点：头/躯干形变 | 见 11.4（这一项**保留逐图元**，但只在鼠标真的在动时才算） |

**一次动作的开销从"图元数"变成"骨骼数"**：26 个部件 + 约 30 个子骨骼 ≈ **60 个容器**。

## 11.3 负载账（用真实图元分布算）

本项目 10030 个图元的分布：

| 组 | 图元数 | 占比 |
|---|---|---|
| bangs（前发） | 2740 | 27% |
| head（脸+五官） | 2020 | 20% |
| body（衣服/围巾/后布/裤） | 1750 | 17% |
| legs（腿） | 1480 | 14% |
| armL / armR | 890 | 9% |
| tailL / tailR / ribbon / hairBack | 1150 | 12% |
| **头部件组合计** | **5610** | **55%** |

对照现在的实测负载（9941 个控件，`updateStride=2` = 30Hz）：

| 状态 | 现在 | 层级化之后（预估） | 降幅 |
|---|---|---|---|
| 空转（鼠标不动） | 866 写入/帧（52k/秒） | **26~52 写入/帧** | **≈95%** |
| 鼠标移动 | 3286 写入/帧（197k/秒） | 120~240 写入/帧 | **≈93%** |
| 首次创建成本 | 9941 个控件 | **不变**（还是 9941 个控件，只是多了 60 个父容器） | — |

**注意最后一行**：层级化降的是**每帧写入**，不是**控件数量**。
9941 个图元控件照样要建、要占布局开销。想同时降静态成本仍然要看
"烘一张整身贴图 + 条带位移"那条路（见 `04`）。

## 11.4 会失去什么：逐图元形变，以及怎么补

层级化的代价很明确：**父容器内的图元只能一起做刚性变换**，做不了"同一部件内每个图元不一样的位移"。
我们目前有三处依赖这个：

| 逐图元形变 | 为什么需要 | 层级化之后怎么办 |
|---|---|---|
| **头部柱面绕**：`Δx = w(cosθ−1) + (z/R)·swing·k` | 让"转头"读起来是转、且轮廓边缘不滑动 | **保留逐图元**，但只作用于**脸+五官那 2020 个**，且只在鼠标真的在动时算（`gazeEps` 闸门已经做到：不动时 0 写入） |
| **躯干位移场**：`Δx = gx·bodyAmp·s(y)·(1+depthK·d(x))` | 髋线以下钉住、越往上越大、无接缝 | 用 **3~4 个子容器**（髋 / 腰 / 胸 / 颈）各转一点近似，误差比"按部件给权重"小得多（因为容器是**嵌套**的，位移天然连续） |
| **手臂弯 / 发丝甩 / 跳跃权重** | 分段感、跟随过冲 | **子骨骼容器**：发根→发中→发梢、上臂→前臂；跳跃用髋/大腿/小腿 |

**关键认识**：嵌套容器给出的是**层级链式变换**，它在数学上天然连续 ——
所以之前那条"相邻部件位移必须一致，否则撕开"的硬约束**自动满足**，
比我们的位移场更好（不会有条带量化、也不需要在算法里消缝）。

### 剩下的"真正交互"部分

视点跟随里，**头的柱面形变**是唯一必须逐图元的部分。改进思路：
1. 用**头容器**承载整体转向（1~2 次写入）
2. 柱面形变只在鼠标移动时叠加（现有闸门已保证静止时为 0）
3. 若还是嫌贵：把柱面形变降级为"只对**脸部**（不含五官）做"，或只对头部做**两段子骨骼**近似

## 11.5 坐标要改：子控件相对父容器

这是迁移时**最容易踩**的一处：控件 `SetAnchoredPosition` 是**相对父控件**的。

现在所有图元都是 root 的子控件，位置 = 源图像素 → 画布空间 → 减半画布。
层级化之后：

```
容器放在部件轴心（pivot）：place(container, pivotX, pivotY)
图元的 anchoredPosition = 它在容器坐标系里的位置
                       = 画布空间位置 - 容器位置
```

我们现有的 `place()` 只要改成"相对容器"，并且**容器自己用部件轴心摆放** ——
旋转也就自然绕轴心了（不需要再自己算绕轴心的位移）。

**副作用**：容器的 pivot/anchors 要设成 (0.5, 0.5)，子控件的锚点也设 (0.5, 0.5)，
这样 `anchoredPosition` 的语义就是"相对容器中心的偏移"，和现在的算法最接近。

| 未知项 | 为什么要紧 | 探测脚本对应段 |

## 11.7 迁移方案（探测通过后）

分三步走，**每步都能单独验收**：

1. **只加一层容器，不改变换逻辑**
   构建脚本把每个部件的图元挂到该部件的容器下（容器放在轴心，图元坐标减去轴心）。
   动作逻辑先把"逐图元写入"换成"写容器"，但**保留**逐图元路径做对照。
   验收：画面与之前**逐像素一致**（除了柱面形变/躯干场这类内部形变先按容器近似）。
2. **补子骨骼**
   头发→发根/发中/发梢，手臂→上臂/前臂，腿→大腿/小腿，躯干→髋/腰/胸。
   把"按离轴距离加转角"换成"逐级容器给不同转角"。
   验收：甩发/摆臂的观感与 `05` 里的参数曲线对齐；无接缝（层级天然连续）。
3. **把逐图元路径收缩到只剩"头部柱面形变"**
   并给它加闸门：鼠标不动 → 一次都不算。
   验收：空转 `writes/frame` 降到 **< 100**；移动时的峰值明显低于现在。

**回退**：第 1 步就保留 `CFG.hierarchy = "flat" | "container"` 开关，
出问题就切回平铺（现在的实现），不会把已经跑通的版本弄坏。

## 11.8 规则 / 不变量

- **同一骨骼的图元要挂在同一个父容器下**：混着挂（一部分挂容器、一部分挂 root）
  会出现两套坐标系，容易错。
- **容器放在部件的旋转轴心上**，图元坐标改成"相对容器"，旋转交给容器。
- **相邻容器别给不同的"位置权重"** —— 用**嵌套**（父→子）表达层级，变换天然连续；
  同级容器之间只允许"整体位移一致"的差异（否则就是 `05` 里那道缝）。
- 容器也要参与**层序**：容器之间的先后由容器在 root 下的同级索引决定，
  容器内部的顺序由子控件在容器内的索引决定 —— 两者都要显式设置。
- 我们把逐图元路径收缩到**只剩头部柱面形变**，并且只在"鼠标真的在动"时才走
  （要保留别的逐图元效果也可以，代价就是那些图元每帧都要写）。
- 迁移时留一个开关（`CFG.hierarchy = "flat" | "container"`），出问题能切回平铺。
- ⚠️ 未验证：子控件数量上限、旋转是否传递、父 alpha 是否传递、容器模板 ID、
  以及容器是否会影响 `SetSiblingIndex` 的语义。
