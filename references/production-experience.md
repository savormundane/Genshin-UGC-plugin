# 可复用制作经验

本页仅保存方法与判断，不包含原游戏规则、数值配置、剧情或资产。来源见 [核心来源](sources-and-conflicts.md)。

## 从单机改多人

先画出配置、规划、执行、结果核对和离线处理的阶段关系。所有包用对局标识和回合标识，避免旧包重播；按席位保留确认记录，而非只显示最新一条。固定真人与补位 AI 席位顺序，所有客户端用相同种子和一致的遍历顺序计算 AI。超时、离线、取消和重开是单独的状态转换，不是界面按钮各自修改局部状态。

客户端日志出现“发送”不能证明服务器接收。无计票时依次查服务器实体挂载、信号声明、引脚类型与顺序、发送目标、来源实体、阶段判定与回包。不先用循环重发掩盖接线错误。来源实体与协议席位不能互相替代为可信认证；仅靠诚实上报的兼容回退需要明确同步试玩局限。

确认允许撤回时，将对局、回合和方案修订一起纳入去重及接受条件。撤回请求尚未确认时显示等待，旧确认不能再次锁住已撤回的新方案。恢复快照包含全员确认集合、本人锁定方案、当前阶段和执行完成屏障；恢复规划页不等于可以重新编辑正在执行的方案。完成屏障按在线有效席位推进，重发不重复完成。

房间显示的开局配置来自权威汇总结果，本人选项与最终结果分开。准备、取消准备、配置改变及倒计时撤销由同一状态机管理，不能只改按钮文字。资源和状态只按当前公开合同显示；恢复、旁观、淘汰和结果页也要检查，不因增加状态栏就泄露隐藏资源。

## 页面与设备适配

全屏背景继续使用覆盖策略，内容区用自身适配规则。不要为露出原生退出/聊天而缩小背景或整体移动页面。服务器原生 UI 和客户端控件有各自渲染边界；客户端同级重排不代表能覆盖原生按钮。实机失败时保存复现、原生按钮状态和层级设置，不凭样式修改声称已解决。

显隐和命中是两条链：隐藏文字、改变 alpha、调整图层并不必然关闭点击。按钮背景、文字、边框及命中区同步布局；不交互的图元关闭命中；阻止背景穿透时保留顶层按钮的触控能力。反复刷新用绝对布局坐标，避免在旧位置上不断加偏移。

大人数状态栏不依赖单文本换行与过小自适应字号，将姓名、状态和资源拆为独立单行控件；同时检查最长名字、最多席位、淘汰状态和结果明细。PC 与手机分支按用户要求单独修改；只修改 PC 时不得顺便改变已接受的手机布局。

同一区域由一处布局逻辑拥有坐标、间距和尺寸，页面刷新只更新状态，不在多个回调里重复修位置。对齐文字、背景及命中框后，再检查普通字号、大字、最长文案及页面往返；减少遮罩须同时检查文字对比度和底层命中。

键鼠共用同一动作入口和禁用条件，快捷键只对当前可操作页面生效。按下与松开维护一次按压状态，等待回包时禁止重复提交；弹窗打开屏蔽底层动作，关闭后不能把仍按住的键当作新按下。切页、启停和销毁清理对应状态及监听。失焦行为须使用已支持的宿主接口另测，不能用OnDisable测试冒充真实切出窗口验证，也不编造窗口焦点API。

常用提示与实际绑定同源或集中维护，重复刷新不重复追加；PC提示不自动出现在手机。给结算、重开等不可逆操作设置快捷键前核对误触成本。平台原生退出与Lua导航分开，不能承诺Lua能拦截系统Esc；具体按键由项目决定，不固化成平台默认。

## 玩法、AI 和教程验证

新增能力要列全生命周期：可选择、可取消、确认、消耗、执行、生效、清除、下一回合和重开恢复；碰撞、墙、显示、AI 和教程必须引用同一规则。伤害事件与显示表现分开记录，双方碰撞统一登记，再把局部碰撞位置与玩家表现一起更新。

AI 不只优化随机风格；观察开局资源使用、原地往返、路线重复、风险和收益。对相同种子回放可复现，新增策略比较安全路线、进攻机会和资源保留，避免为了“聪明”提前看见未公开的真人路线。

先列出普通单人、闯关、多人补位、训练、固定挑战和回放等实际调用入口，核对算法、参数、随机来源和兼容分支。受保护的历史挑战保留旧算法与计分条件；新规则改变确定性结果时联动规则标识、握手及录制兼容检查，不把旧纪录直接并入新条件排名。

AI输入限制在公开局面、已执行历史及该席位允许知道的本人资源。用同一公开快照、种子和本人资源，仅扰动他人私有方案或隐藏资源，验证结果不变；另设允许本人资源改变决策的对照。隐藏字段未用于最终评分还不够，也要检查候选生成、剪枝和随机种子。各席位使用可重建的确定性随机来源，本地UI操作不消耗共享序列；需要目标连续性时由共同历史重建，不增加仅本机持有的战术记忆。

战术评价先排除非法或已知自毁，再比较公开风险，在相近风险下评估争位、封路、脱困、后续退路和资源成本。路线与资源使用作为完整方案评估，不用贴近对手或无收益消耗代替进攻。近分随机限于战术目的相近的方案；狭窄空间的必要折返不等于无效循环。搜索预算和超时降级明确，不能靠无限加深搜索掩盖评价问题。

避险、争位、资源使用、循环及残局等场景分别保留“应选”和“应放弃”的见证，验证行为及淘汰原因。之后用相同种子、布局与席位交换做开发对照；冻结候选后再看独立留出结果，继续调参就不再称其为未见数据。分别报告可避免死亡、自困、重复边、平局、资源收益和计算耗时；某项改善而另项变差时保留差异，不宣称总体智能已验收。最大配置与多客户端确定性单测不能替代真人战术体验。

强制教程由可观察的完成条件推进，不用文案提示替代条件；每一步限制不相关操作，演示结束保留观察时间，再转到规则说明。是否单人可用、终点筑墙、护盾及键位等内容来自当前项目，不复制旧游戏参数。

关卡按完整课程维护学习目标、引入规则、对手能力、攻略和应变说明。共用AI改变后复核所有受影响关卡，不只抽查开头、结尾或新增章节。攻略通过真实规则操作执行，达到胜利即停止，不能靠步骤尾部未执行的动作证明路线。若要求第二条解法，排除等待、时间标记和胜利后的无效尾部后仍应具有实际不同的空间或决策路线。夹具解锁、模型有解及真人学习曲线分别记录；玩家偏离攻略后能否理解并应变仍需体验观察。

## 存档与节点

用户在编辑器加入音乐、退出保护或其他设置后，先与上一份交付做字段差异，后续以用户的新文件为基线。修改内嵌脚本与图的同时，校验映射、挂载与唯一性，交付一份整合文件时不能仍依赖旧本地路径。

二进制节点数与编辑器计数不是同一口径，低于报错阈值也不能保证导入。优化重复读取节点时保留执行顺序、分支语义和信号入口；考虑输出扇出和复合节点展开。逐项报告优化前后数量，编辑器未测试则保留未验证标记。

Python 模型可能落后于最终服务端源码。验证时以实际生成图及最终脚本为对象，模型只是辅助；历史“通过”不自动覆盖后续版本。结构检查、源码模拟、Lua 模拟、视觉预览、编辑器导入、真实多人试玩分开记录。

图转换后的新增节点也必须参与最终重接，沿实际输出声明核对类型；引用存在不足以保证写入值正确。保存排查按首次读、业务更新、写入、回读、离场、重进首次读分别取证。具体检查和狭窄空档恢复边界见 [原生数据流与跨次存档排障](native-dataflow-validation.md)。

退出按钮、结算资格、本人存档确认和多人结束同意各有状态，不能用一个“已完成”标记包办。多人回落单人时重算当前可用动作；取消退出意图不擅自清除在途保存。结算等待须有失败原因与重试路径，不用二次点击跳过数据保护。

## 回归与最终交付

客户端测试及预览共享明确版本的宿主模型，不从其他测试截取零散mock。未实现API、错误字段、非法父级和只读写入应显式失败；扩充模型时先查真实API并增加对应边界检查。真实Lua执行、模拟信号、实际服务端源码模型与最终原生图分别标明，逻辑相似不能替代最终接线回读。

冻结源码后记录摘要，按当前构建入口从只读基底向独立输出重建，再核对嵌入Lua、声明、图、挂载及保护字段。仅改文字或版本时可用精确差异加受影响复查承接既有证据，但须说明继承范围，不能把旧完整回归写成本版重新全跑。

失败报告保留原文。旧断言依赖过时数量、键位或流程时，先证明合同已变，再调整夹具并保留业务不变量；不能为满足旧测试恢复已取消功能或放宽保护。候选源码再次改变后，重新绑定证据摘要，不覆盖旧报告制造连续通过。历史交付按所属项目保留合同处理，不清空含人工数据的dist或outputs，也不重跑历史升级脚本作为当前构建。

## 能力边界

关卡内投票计时不是进入关卡前的原生匹配时限；未找到匹配接口时不能用局内计时冒充。背景音乐配置索引不等于 game.PlayAudio2D 的音效 ID。本地音频路径也不是已导入资产索引。阵营结算要确认玩家分组及结算配置，不能把全关卡结算按钮称为单人退出。


## 离线节点图与 UI 文件转换

Graph Code 属于节点图 DSL，先严格解析，再校验项目作用域的 GUID、挂载、类型与资源引用。HTML 修改后重新生成 bundle，绑定对应 UI GUID 导出记录，再生成文件。Graph IR 与 GraphModel 区分输入模式；导出后回读节点、边、信号和变量合同。工具成功退出不代替编辑器与运行验证。


## 多图与原生交付经验

多图任务按事件、状态和宿主拆分，以显式协议连接。信号定义、关联节点声明和实际引脚同步核对；整数常量与泛型包装按当前样本保持一致。静态节点计数、编译结果与编辑器展开计数分开记录；只读查询去重也要核对目标、时机和扇出。平台存档配置、客户端编码和平台实际跨次读写分别验收；计时和重置按权威端合同实施。当前基底新增配置优先保留，不能用历史空基底覆盖。具体构建见 [节点图制作](node-graph-workflow.md)。


新图写回要比较源码声明与输出变量表，避免继承校准模板中的未使用图变量。只有明确未声明且未被节点引用的新增图变量可以定向清理，原有图变量不在此清理范围。隐式未使用端口、空表占位与实际业务端口分开统计；连接、数据输入类型和常量独立回读。


## 完整生成所需的组装经验

完整游戏应先交付进入、首轮操作、胜败、重开的闭环，再叠成长与内容量。脚本替换、原生图变更、资源封装有不同构建输入；不能把客户端打包入口当作全量关卡构建器。构建清单记录基底、映射、挂载、生成顺序、产物摘要和未验收阶段。

自定义信号、结构体及辅助节点共享定义空间时统一扫描分配。声明的多种通信角色、实例端口、泛型具体类型和变参数量应独立校验；仅节点编号与数量正确仍可能被编辑器拒绝。

持久化先读后写，读取失败不得清空原档；迟到回包按字段业务语义合并。损坏可选档位不阻断正常进度。保存、变量回读、结算和平台离场落盘分段记录；缓存一致不能冒充一次新的写入，成功反馈绑定具体交付摘要。检查点恢复不能重复发奖或重抽报价。详细编排见 [一句话制作工作流](one-sentence-workflow.md)。

## 设计新功能与保护已有合同

不得猜测已有信号、平台标识和字段语义，不等于不能设计新协议。新图/变量/信号由Agent定义并同步两端，作用域内扫描编号冲突。无现成生成器时先写当前项目补丁并核验，再判断是否抽成通用工具；用户需要的是具体实现，不应被要求先完成通用框架。详见 [主动实现](implementation-policy.md)。
