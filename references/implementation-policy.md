# 主动实现与合同设计

## 默认推进方式

用户要求制作或修复玩法时，Agent负责设计、编写节点图与客户端、连接协议、生成资源/文件补丁、整合及验证，持续完成已授权交付。技能是同一任务的能力分工，不要求用户逐个点名，不把转交另一技能当作结束。没有全自动构建器、通用模板或现成补丁命令，不构成无法完成具体项目的理由。

规划后直接实施。已有信息足够时自行确定可逆细节并记录假设。需要编辑器/实机验证不阻止完成源码、图、文件写回及离线检查；最后把尚未执行的验收单独说明。不得为了显得完成而删除功能、输出空图、伪造回执、跳过类型校验或宣称宿主已通过。

## 按来源处理合同与标识

| 类型 | Agent的动作 |
| --- | --- |
| 新功能协议、变量、图内节点索引、项目自定义定义 | 自行设计名称、类型、方向、顺序、生命周期和错误处理；在当前作用域扫描冲突，按格式允许的命名空间分配并记录；同步实现发送、监听、声明及实例 |
| 已有协议、保存格式、图/模板/实体映射 | 从当前文件读取，核对调用方和实际字段；需要改变时明确迁移和兼容范围，不把新设计说成原来已有 |
| 平台内置节点、API及平台资产/配置标识 | 查官方资料、内置节点定义和真实文件；不能发明接口或把任意数字称为平台已注册资源 |
| 新实体、模板和挂载 | 当前文件模型或已核验样本允许创建时，由Agent创建、分配标识并写入引用；完成唯一性、依赖及回读核验，不默认已有挂载 |
| 无法自行获得的必要输入 | 先查当前文件、工具和可用参考；仅对确实缺少的平台配置、类型样本、私有资源或会改变玩法的关键选择提出具体问题，继续完成不依赖该输入的工作 |

“不得猜测已有合同”限制的是把未知既有事实当真，不禁止为新功能制定合同。新信号不需要用户先报名称；已确定的玩法不需要用户手动画执行线。自定义编号可分配不等于任意平台资产ID都能分配。

## 工具与实现责任

现有脚本的边界是该脚本当前做什么，不是Agent整体只能做什么。先选择已有严格Graph Code链路或已核验文件接口；不支持的部分读取真实声明/结构后写当前项目的生成器、局部补丁或适配脚本，使用独立输出和失败拒绝。证明可复用后才进入公共工具，不为统一形式重写已有可靠项目链路。

required_mounts只检查已有绑定；需要新挂载时先按真实实体/模板结构完成写回，再使用它或独立回读核验。Lua替换命令只改脚本；图、资源与信号变更由Agent完成对应步骤后再整合，不能因为单条命令不支持而让用户承担全部组装。

新工具可能需要真实结构样本，先搜索当前基底、包内节点库和已提供资料。确实没有可验证依据时准确列出缺失结构、已尝试路径、可以继续的部分和最小补充；不得盲改未知二进制。离线检查不能证明任意节点的运行语义。

## 每次实际交付

核对需求中的每个行为对应哪段源码、事件/执行线/数据线、状态及资源；交付当前源码和所需整合文件。分别报告编译、回读、挂载、模拟、编辑器与实机证据。只因设备验收尚未执行，不把已完成实现降格成纯计划；也不把实现完成等同于设备通过。
