# 05 · 动作与骨骼

这一节是"怎么让它活起来"。核心结论先给：

> **相邻或重叠的部件，在同一位置的位移必须一致。**
> 最省事的满足方式是**连续位移场**：位移是 (x,y) 的连续函数，相邻图元拿到的值只差一点点，
> "部件边界"这个概念在算法里直接消失。
> 按部件给权重则必然在边界撕开——本项目实测腰部裂了 **4.2px**
> （身体转 1.6°、腿只转 0.48°，200px 力臂上就是 4px 的缝）。
>
> 这不是"必须照我们的公式写"，而是**必须满足这个条件**；手段可以换（见 5.6）。

---

## 5.1 呼吸：一切的基础

> 实现方式有两种：**逐图元写**（下面这种，现在跑通的版本）和
> **挂父容器只动容器**（每帧写入降到几十次，见 `11-层级与骨骼-父容器.md`）。
> 公式本身两种都用，只是"施加对象"不同：前者施加到每个图元，后者施加到部件容器。

```lua
local vB = math.sin(TAU * (t - (p.delay or 0)) / CFG.period)
dy  = dy - CFG.baseAmp * CFG.ampScale * p.w * vB   -- 源像素；负号 = 向上
rot = rot + (p.rot or 0) * vB
```

- `period` = 呼吸周期（本项目 3.6 秒）
- `w` / `delay` / `rot` 全部来自 `attachments/l2d_rig.json`（见 `01`）
- **`delay` 是"次级运动"的来源**：发丝比身体慢半拍，读起来就有生命感
- `baseAmp` 本项目压到 **1.2**（原 rig 给 3.6，实机放大 1.05 倍后头肩起伏到 15px，实测期望只有 ~3px）

## 5.2 眨眼：几何**从数据推**，不要手填

关键洞察：

> **虹膜和眼白要分成两个部件。** 原因很直接：它们在同一帧里的变换不一样
> （虹膜跟着视点滑动，眼白留在原地）。**变换不同的东西就得分开**，
> 否则只能一起动，读起来是「整个眼球在平移」而不是瞳孔在动。

角色划分（按部件编号，本项目）：

| role | 部件 | 做什么 |
|---|---|---|
| `iris` | 9（左）、11（右） | 随视点滑动 |
| `eye` | 10（左）、12（右） | 眼白，随眨眼**纵向压缩** |
| `lid` | 6、7（左）、8（右） | 睫毛/眼线，下移到闭合线 |
| `brow` | 2（左）、3（右） | 眉毛（可选跟随） |

几何从图元包围盒算，不手填：

```lua
eye.top   = (虹膜 ∪ 眼白) 的 y 最小值
eye.bot   = 同上的 y 最大值
eye.lidCy = (睫毛 ∪ 眼线) 的 y 中心
闭合线 ty = top + closeAt * (bot - top)        -- closeAt = 0.78（≈下眼睑位置）
```

三件事必须同时做，缺一个就看不出"闭上"：

1. **眼内容绕闭合线纵向压缩**：`ny = ty + (ny - ty) * sc`，`sc = 1 - maxClose * v`（maxClose 0.92）
2. **眼睑线下移到同一条闭合线**：两者落在一条线上才读得出闭眼
3. **眼内容随闭合淡出**：否则眼白压扁后留一条淡色带，像"厚嘴唇"

闭合剖面：**前 40% 时间闭合、后 60% 张开**（真人也是闭得快、睁得慢）：

```lua
if u < 0.4 then p = 0.5 - 0.5 * math.cos(math.pi * u / 0.4)
else p = 0.5 + 0.5 * math.cos(math.pi * (u - 0.4) / 0.6) end
```

### 三个实测踩过的 bug

| bug | 症状 | 根因 |
|---|---|---|
| 眼白不眨眼 | 只有虹膜在动 | 生成器写的 role 是 `eye`，Lua 里判断的是 `sclera` —— 名字对不上 |
| 眨完眼眼睛没恢复 | 一直保持细长 | 只在 `nh ≠ s.h` 时写回尺寸，压缩后又恢复时恰好相等 → 没写 |
| 恢复睁眼后 alpha 不还原 | 眼睛一直是淡的 | 淡出/还原的标志位写进了**逐图元循环**，被第一个图元清掉了。必须按**部件**判定一次 |

### 左右不同步

`skewMs`（本项目 12ms）给左右眼一点相位差，避免完全同步（同步会显得很假）。
另外有 `doubleChance`（0.16）概率连眨两下。

## 5.3 视点跟随：眼球 + 头 + 身体

分三层，**权重完全不同的性质**：

| 层 | 手段 | 说明 |
|---|---|---|
| **眼球** | 虹膜滑动 | 主动作。**受限**，见下 |
| **头** | 柱面形变（内部形变） | 头**不做整体平移**——平移是"滑动"，形变才是"转头" |
| **身体** | 躯干位移场 | 越往上越大，脚钉住 |

### 眼球：API 没有 stencil 掩膜，只能限幅

`enableMask` 是**矩形区域遮罩**（`reverseMaskArea` 决定是否反转），**不是按图片 alpha 的模板**，
所以裁不出眼型。于是只剩两条路：

- **限幅**（本项目 Lua 采用）：量出"虹膜整块都在合法区内"的最大位移
- 掩膜裁剪（只有浏览器预览能做：Canvas 的 `destination-in` 可以按眼型裁）

限幅值是从原图 alpha 量出来的，**严重不对称**：

```
左眼 {左 5, 右 0, 上 3, 下 0}     右眼 {左 0, 右 0, 上 7, 下 0}   （源像素）
```

因为虹膜本来就在某几侧贴着边界。**代价**：实机里往右看、往下看时瞳孔不会动，
方向感主要由头/身体/发丝读出来。这是我们接受的取舍（硬拉过去会更露馅）；
如果以后找到了能做眼型掩膜的办法，这里可以改回完整跟随。

### 头部：柱面形变（不是平移）

把头部想象成一根柱子，绕它转：

```lua
w  = s.x - HEAD.hx                    -- 离头部中线的水平距离
z  = sqrt(HEAD.rx² - w²)              -- 该处的"深度"
nx = nx + w * (cos(θ) - 1)            -- ① 压缩项：远端收窄，轮廓边缘几乎不动
       + (z / HEAD.rx) * swing * k     -- ② 摆幅项：正前方摆得最多
```

- **① 压缩项**让轮廓边缘几乎不动 → 不会和脖子/背景脱开
- **② 摆幅项**按深度 `z/R` 衰减 → 层的**前后关系**就出来了（视差）
- `k` 是**层间深度系数**：虹膜 1.30 > 五官 1.14 > 嘴 1.10 > 前发 1.05 > 脸 1.00 >
  后发 0.85 > 发尾 0.80。前景动得多、背景动得少，就是立体感的来源
- 头部圆柱的**中心与半径从数据推**（头部件组的并集 bbox），不手填

**两个必须解耦的参数**："头部半宽"（本项目 159px，含头发）和"前后深度"不是一回事。
用同一个半径会让摆幅直接爆掉——实测会到 35~50px。

### 身体：躯干位移场（三段斜坡）

```
Δx = gx · bodyAmp · s(y) · (1 + depthK · d(x))
Δy = -gx · bodyAmp · depthK · tiltK · s(y) · d(x)
```

| 段 | y 范围 | s(y) | 含义 |
|---|---|---|---|
| ① | y ≥ yHip（髋线以下） | **0** | 腿脚**自动钉住**，不需要单独给腿权重 |
| ② | yHip → yNeck | 0 → 1 | 胸口转得最多，"身体在转"就读出来了 |
| ③ | yNeck → yTop | 1 → **headKeep**(0.25) | **脖子吸收掉大部分转角** |

第 ③ 段是关键：头自己已经有一整套柱面形变，再叠加满幅整体平移就变成"整颗头在横滑"——
正是用户否掉的那个效果。让脖子吸收掉，头就只保留形变。

本项目实测锚点（自动从数据推）：`yGround=594.5, yHip=380.3, yNeck=318.9, yTop=99.8,
cxTorso=214.5, rxTorso=98`。

参数：`bodyAmp=6`（胸口最大水平位移，源像素）、`depthK=0.25`（伪深度压缩）、`tiltK=0.10`（轻微歪斜）。

**实测振幅画像**（鼠标左右扫 3 秒，代表图元）：

| | 水平 | 竖直 |
|---|---|---|
| 脚 | **0.00px** | 0.00px |
| 躯干 | 0.66px | 2.12px |
| 头 | 17.29px | 3.87px |

对照旧版"按部件权重"：6.96 / 8.59 / 21.6px —— 脚在动、脖子断层。

### 手臂骨与发丝骨：用"离轴距离"当参数

```
extra = dynRot × armBend / hairWhip × t        t = 该图元离轴心的归一化距离 ∈ [0,1]
```

转角随距离增长 → 读成**肩→肘→手**、**发根→发梢**的分段，而不是整条刚性转。
`armBend=0.55`（末端多转 55%）、`hairWhip=0.85`。
`t` 是几何量，**加载时算一次**（放进每帧循环就是白烧 CPU）。

驱动量用 `dynRot`（**通道+视点**的转动，**不含呼吸**）——呼吸是整体慢起伏，不该当甩动的驱动。

## 5.4 跳跃：关键帧轨迹，不是正弦

跳跃的节奏（下蹲→蹬地→腾空→落地缓冲）不是正弦能表达的，所以单独一条关键帧轨迹：

```lua
-- 每行 = {秒, 下蹲系数, 摆臂系数, 发梢滞后系数}；三次平滑插值（smoothstep）
local JUMP_KEYS = {
  {0,     0,    0,     0},
  {0.22,  1,   -0.35,  0.2},     -- 下蹲到最深
  {0.32,  0,    0.8,   0.6},     -- 起跳
  {0.48,  0.25, 1,    -0.65},
  {0.60,  0.45, 0.8,  -1},       -- 最高点附近
  {0.84,  0,    0.3,   0.5},     -- 落地
  {0.96,  0.75,-0.2,   1},       -- 落地缓冲
  {1.12, -0.12, 0.1,  -0.3},
  {1.35,  0,    0,     0},
}
-- 腾空高度不在表里，是一条单独的抛物线（0.32s 起跳、0.84s 落地）
jump.height = 4 * CFG.jump.height * u * (1 - u)
```

每个图元预计算三个权重（几何量，加载时算一次）：

| 权重 | 含义 |
|---|---|
| `jHip` | 髋部以下渐弱 → 脚踝以下 ≈ 0，脚只跟根位移走 |
| `jKnee` | 膝部权重 → 下蹲时把小腿沿 x 向外撑开 |
| `jSide` | 相对中线的横向归一化，决定"往外撑"的方向 |

幅度（本项目，实机调出来的）：`height=64, crouch=24, knee=10, arm=12, hair=3.5`。
锚点：髋 392 → 膝 480 → 踝 560，中线 x=218（**源坐标 Y 向下**）。

### 三个容易出错的点

1. **跳跃位移要放在"表情之后"施加**：根位移必须跟眼睛/睫毛/眉毛一起走，
   否则眨眼时眼球留在原地、脸飞上去。
2. **恢复帧要把写入阈值压到 0**：跳跃结束那一帧的位移小于 `posEps` 会被写入缓存吃掉，
   角色会**停在半空/半蹲**。
3. **不叠加**：上一次还没落地就不受理新的，否则腾空高度会累积。

绑定按键时注意：跳跃用的是**独立的** `KeyboardJumpKeyDown`（空格），不属于"奇匠按键"那一组。

## 5.5 动作系统：连续通道 + 一次性动作

两层叠加：

```lua
通道有效值 = 连续开关(CFG.ch[name]) × 强度 + Σ 正在播的一次性动作包络
```

- **连续通道**：`sway`(摆动) / `turn`(转头) / `nod`(点头) / `wind`(风吹) / `armR`(摆臂)，
  每个是一条正弦，按**组权重**分配
- **一次性动作**：`shake`(摇头) / `nodOnce`(点头) / `surprise`(惊讶) / `wave`(摆臂) / `jump`(跳跃)，
  各有 dur 秒的包络，`pulse(u,a,w)` 做"快起、保持、稍慢落"

### 一个容易踩的写法

每帧重算通道值时，遍历固定的 `CHANNELS` 清单（而不是 `CFG.ch`）就不会踩这个坑：

```lua
local CHANNELS = { "sway","turn","nod","wind","armR","talk","eyeOpen","browRaise" }
```

**原因**：切预设时如果把 `CFG.ch` 换成空表，遍历等于什么都没做，
`chv` 里的旧值就挂在那儿了 —— 实测"说话 → 全停"之后说话通道还是 1。

### 摆臂要按部件编号定向

`armR` 在我们的 rig 里只该动右臂（部件 24）：按组给权重会把左臂一起带上。

## 5.6 规则分成两栏

### 必须满足（不满足就坏）

这些是数学/物理层面的要求，换任何实现方式都绕不开：

- **相邻或重叠的部件，在同一位置的位移必须一致**（或差异小到看不见）。
  否则边界必然开缝 —— 实测裂缝能到 4.2px。
  满足它的手段不止一种：连续位移场（我们用的）、把相邻部件并成一组共用同一个变换、
  或保证接缝处被别的东西盖住。
- **每帧重算的通道必须覆盖全部通道**，不能只遍历"当前配置里出现过的"——
  否则切预设时会留下上一套的残值（实测"说话→全停"之后说话还是 1）。
- **眼/眉/嘴这类特殊部件，生成器与运行时的角色定义必须来自同一处**（同一份表、或同一套命名规则），
  否则名字对不上就会静默失效（实测"眼白不眨眼"就是这个）。
- **眨眼的淡出/还原标志按部件判定**，不能放进逐图元循环（会被第一个图元清掉）。
- **跳跃这类"回到原位"的动画，最后一帧必须精确写回**——
  写入缓存会把恢复帧的小位移吃掉，角色停在半空。

### 参考实现（可以不同）

| 我们的做法 | 可以这样 |
|---|---|
| 连续位移场 `Δ = F(x,y)`（含三段斜坡） | 骨骼层级 + 蒙皮权重；或把相邻部件合并成一组 |
| 躯干斜坡：髋=0 → 脖=1 → 头顶=headKeep | 任意曲线，只要**脚≈0** 且**越往上越大**（见验收表） |
| 头**不做整体平移**，只做柱面形变 | 也可以给一点整体平移，只要**看起来是"转"不是"滑"** |
| 柱面公式 `w(cosθ-1) + (z/R)·swing·k` | 任何内部形变都行；`k` 的层间深度系数是我们的取值 |
| 手臂/发丝用"离轴距离"当弯曲参数 | 也可以分两段骨骼节点实现 |
| 虹膜**限幅**（Lua 没有眼型掩膜） | 若找到能做 stencil 的方法就用，效果更好 |
| 跳跃用关键帧 + 抛物线 | 正弦叠加也行；只要节奏读起来像跳跃 |
| 呼吸/通道/一次动作这套参数 | 幅度、周期、包络都按你的角色调 |

### 验收：怎么确认"动作做对了"

| 要保证 | 怎么量 |
|---|---|
| 脚钉住 | 脚部图元水平位移 ≈ 0（本 0.00px） |
| 越往上动越多 | 躯干/头位移单调递增、无台阶（本 0.66 → 17.29px） |
| 无接缝 | 扫一遍位移场，相邻 2px 采样的差 < 0.5px；或肉眼放大看腰/脖子 |
| 头读成"转"不是"滑" | 看轮廓边缘与中心是否**不同步**（整块同速平移就是滑） |
| 眨眼读得出 | 眼内容压缩数 + alpha 变化数 + 能还原，三者都要有（本 681/681/681） |
| 动作互不干扰 | 逐动作量位移峰值，每个都非零、且不改变别的动作的数字 |
| 视点自然 | 眼球/头/身体/发丝四层动得不一样（分层才是立体感） |

## 5.7 常见错误

| 现象 | 原因 |
|---|---|
| 腰部/脖子撕开一条缝 | 相邻部件位移函数不同（用了按部件的权重） |
| 整颗头在横滑 | 头吃到了满幅躯干场平移，或头部有整体平移 |
| 脚在地上滑 | 躯干斜坡的 0 点没放在髋线，放在了脚底 |
| 眨眼后眼睛没恢复 | 尺寸只在 `nh ≠ s.h` 时写回；淡出标志写进了逐图元循环 |
| 眼白不眨眼 | role 名字和生成器不一致 |
| 切预设后旧通道还在生效 | 遍历了 `CFG.ch` 而不是固定通道清单 |
| 跳跃落地后停在半空 | 恢复帧没把写入阈值压到 0 |
| 跳跃时眨眼、眼球留在原地 | 跳跃位移施加在表情之前 |
