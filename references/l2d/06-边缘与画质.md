# 06 · 边缘与画质

这一节讲"边看起来不对"时怎么办。核心结论：

> **硬边主要取决于贴图边缘，不取决于 alpha 滑杆。**
> **白描边是颜色问题，不是几何问题** —— 所以**不能按颜色（白色）删图元**。

---

## 6.1 硬边：源图是二值的，拟合结果不是

源图层 alpha 严格二值（0/255，见 `01`），而拟合出的图元带抗锯齿与半透明。
把重建结果拉回硬边，杠杆按效果排序：

| 手段 | 效果 |
|---|---|
| **① 贴图边缘（硬边二值贴图）** | 半透明像素 2000 → **690**，**主要杠杆** |
| ② 像素对齐（位置/尺寸取整） | 与源图的半像素错位消失 |
| ③ alpha 丢淡阈值 / 提纯阈值 / 增益 | 只改不透明度分布，**对边缘硬度影响 ±5%** |

**"硬边"的判据是半透明像素数 + 放大镜看，不是 RMSE。**
软边会人为降低 RMSE（半像素错位正好被糊掉），所以"软边 RMSE 更低"是度量假象，不是质量更好。

⚠️ 未验证：游戏里那张圆贴图（`circleAssetId`）本身的硬度。
图片控件有 `enableSoftEdge` 等字段，本项目没有设置——实机若偏软，先试 `enableSoftEdge = false`。

---

## 6.2 白描边：完整因果链

现象：轮廓**外侧**多出一圈 1~3px 的浅色描边，在深色背景上特别明显。

### 因果链（每一环都有实测数据）

```
① 手扣图层的透明区 RGB 是**纯白 (255,255,255)**          ← 26 个部件实测 100% 如此
        ↓
② 细结构部件为了表达勾线，先用 Lanczos 放大 3 倍           ← 见 02
        ↓
③ PIL 的 resize 对 RGBA 四通道**各自独立**插值，不做预乘 alpha
   → 白色被卷进轮廓最外 1~3px 的半透明像素
        ↓
④ 拟合器照着这些**偏亮**像素取样 → 轮廓最外一圈被拟成浅色
        ↓
⑤ 用户看到"边沿几个像素的白色描边"
```

### 关键判据：几何外溢只有 0.68%

实测：10030 个图元里，只有 **90 个（0.90%）** 落在轮廓外，外溢的 alpha 质量只占
重建总质量的 **0.68%**。

**所以这不是"图元画到外面去了"，而是"轮廓最外那圈颜色偏亮"。**
——这一步决定了修法：要修颜色，而不是删图元。

### 反例：为什么不能按"白色"删图元

花朵、衣服金边、瞳孔高光本来就有大片近白像素。按颜色删会直接把它们切掉。
**判据只能用空间（在不在原图内容里），不能用颜色。**

---

## 6.3 我们的修法：三步都在**数据**上做

> 下面这三步是**我们这套**的做法，不是唯一解。要求只有两条：
> ① 判据用空间不用颜色；② 改完内部误差不能变差。具体阈值和步骤随你（见 6.8）。

处理顺序有讲究：**先剔溢出 → 再缩边界 → 最后改色**
（缩边界改了尺寸，颜色取样必须排在它后面，否则取样范围是过时的）。

| 步骤 | 判据 | 用哪个掩膜 | 本项目规模 |
|---|---|---|---|
| ① **剔溢出** | 图元面积落在内容内的比例 < 0.12 → 删 | **本部件自己的** alpha | 90 个 |
| ② **缩回轮廓** | 跨出轮廓 → 绕自身中心缩小到"外面 ≤2%" | **整身并集** alpha | 633 个 |
| ③ **轮廓改色** | 贴着轮廓的图元按原图真值**往暗里**修 | 本部件自己的 alpha | 3841 个 |

### 为什么 ② 是必须的（也是最反直觉的一步）

**真正画出浅色描边的，是一半在里、一半在外的图元。**
轮廓是硬切的，而圆/椭圆是拼接的，边缘总有图元鼓出去 1~3px。删是删不掉的
（它们在轮廓内有内容），只能**缩**。

### 为什么 ② 必须用整身并集，不能用本层 alpha

"超出本层、但被上层盖住"是**正常**的（每层都画满整张画布）。
按本层缩会白掉内容：

| 掩膜选择 | 被动到的图元数 | 五官/睫毛 |
|---|---|---|
| 按本层 alpha | 2883 个 | 被误动 |
| **按整身并集** | **633 个** | **一个都不动** |

### 为什么 ③ 只往暗里修

白边污染**只会让图元比真值更亮**。逐通道只下调、不上调，
这样即使真值和拟合值本来就有偏差，也不会把已经对的地方改坏。

---

## 6.4 实测效果

| 指标 | 修前 | 修后 |
|---|---|---|
| 最外 1px 环「明显偏亮(>25)」像素 | 1568 | **82**（降 95%） |
| 轮廓外溢出质量 | 745 | **333**（降 55%） |
| 内部 RMSE（离轮廓 >3px） | 22.40 | **22.23**（没伤里面） |

验收图：把源图/未修/修复三种并排，**在外缘放大 6 倍**看 —— 白描边只有 1~3px，不放大看不出来。

---

## 6.5 更根本的修法（在上游）

上面三步都是**在拟合输出上打补丁**。根因在第 ③ 步（放大卷边），所以更彻底的做法是：

> **放大部件图前，先把透明区的 RGB 染成邻居的颜色。**

`upscale_edge_aware()`（`attachments/l2d_fit_batch.py`）就是这么做的。
它对拟合是**中性**的：拟合只看 alpha ≥ 阈值的像素，而那些像素的颜色一个都没改，
改的只是透明区里"本来就不该被采样"的 RGB。

**⚠️ 反直觉的实测结论：用"预乘 alpha"反而更糟。**

| 放大方式 | 最外圈（alpha<128）RGB 均值 |
|---|---|
| 直接 Lanczos | (248.6, 244.7, 242.1) |
| 预乘 → 插值 → 反预乘 | **(255.0, 255.0, 254.9)** ← 更白 |
| **先填色 → 插值** | 接近内容色 |

原因：Lanczos 的负瓣过冲会被 `1/alpha` 放大，边缘反而更白。

---

## 6.6 显示层的遮罩：能做，但不该依赖

浏览器预览里可以按原图二值 alpha 把最终合成 `destination-in` 裁一遍，轮廓外溢出质量能到 **0**。

**但 Lua 侧做不到**（没有 stencil 掩膜），所以：

- **不要**用"显示层遮罩"当最终方案 —— 预览里干净、进游戏又脏了
- 遮罩只能当**诊断工具**（判断白描边是不是本来就在原图轮廓内）
- 本项目最终把预览里的遮罩也**去掉了**：数据干净了就不需要它，
  留着反而让预览和实机不一致

## 6.7 验收指标怎么读

| 指标 | 含义 | 健康的量级 |
|---|---|---|
| **半透明像素数** | 边缘硬度 | 源图 0；本项目硬边 ≈ 1136 |
| **轮廓覆盖** | 源图不透明处、重建也覆盖的比例 | > 99% |
| **轮廓不符像素** | 两者轮廓不一致的像素 | < 1% |
| **颜色 RMSE** | 整体颜色误差 | 20~30（硬边比软边略高是正常的） |
| **环带带符号亮度** | 边缘偏亮/偏暗的**系统性偏差** | \|值\| < 3 |
| **环带「明显偏亮(>25)」像素数** | **白描边的直接度量** | 越低越好 |

⚠️ 注意：**比较颜色时必须先把预乘 alpha 还原**（`rgb / alpha`）。
本项目在诊断脚本里踩过：`rasterize` 返回的是预乘色，直接比较会把轮廓像素算得偏暗，
把结论带反（"重建偏暗"），浪费了一轮排查。

## 6.8 规则分成两栏

### 必须满足（不满足就会误伤）

- **"要不要删/缩某个图元"的判据只能用空间（在不在内容里），不能只用颜色。**
  花朵、衣服金边、瞳孔高光本来就有大片近白像素 —— 按颜色删一定误伤。
- **缩边界时，判据要用"角色可见轮廓"，不能用"本层自己的 alpha"。**
  因为本层内容会被上层盖住，按本层缩会把被盖住的部分也削掉
  （本项目：按本层缩会动 2883 个图元，按整身并集只动 633 个，且五官一个不动）。
  如果你的分层是"每层只保留自己的内容"，两者等价，那用哪个都行。
- **边缘修正的副作用必须可量化，且内部误差不能变差。**
  本项目每次改完都复测"内部 RMSE"，防止修边界顺手把里面改坏。
- **做像素比较前先把预乘 alpha 还原**（`rgb / alpha`），否则结论会反
  （本项目就因此把"重建偏亮"误判成"偏暗"，白查一轮）。

### 参考实现（可以不同）

| 我们的做法 | 可以这样 |
|---|---|
| 三步：剔溢出 → 缩边界 → 改色 | 只做其中一两步；或换别的收尾方式 |
| 阈值 0.12（剔）/ 2%（缩）/ 半径 2px（改色） | 按你的素材调；判据是"外溢下降 + 内部不变差" |
| 缩边界时绕图元中心等比缩小 | 也可以只缩长轴、或改用"裁掉越界的那部分"（如果格式支持） |
| 改色只往暗里修 | 取决于污染方向：确认你的污染让它变亮还是变暗，只往那个方向修 |
| 在构建时内存里做、不改 `shapes.json` | 直接改也行，但**留一份原始备份** |
| 放大前先把透明区染成邻居颜色 | 任何能阻止透明区颜色卷进边缘的办法都行 |
| 不用预乘 alpha 做放大 | **这条是实测教训**，不是风格选择：预乘会让边缘更白（见 6.5） |
| 显示层不加遮罩 | 遮罩只能当诊断工具；加了会让预览和实机不一致 |

### 验收：怎么确认边缘这套做对了

| 要保证 | 怎么量 | 参考量级 |
|---|---|---|
| 白描边消掉了 | 最外环「明显偏亮(>25)」像素 | 本项目 1568 → **82** |
| 外溢少了 | 轮廓外 alpha 质量 | 745 → **333**（几何外溢本来就只占 0.68%） |
| 没伤内部 | 内部 RMSE（离轮廓 >3px） | 22.40 → **22.23**（**必须不变差**） |
| 边缘是硬的 | 半透明像素数 | 远低于软边（本硬边 ≈1136，源图 0） |
| 轮廓对得上 | 轮廓覆盖 / 不符像素 | 覆盖 > 98% / 不符 < 2% |
| 修的地方对 | 放大 6 倍看外缘 | 白边明显变淡，且没有出现新缺口 |

**校验方法**：把「源图 / 未修 / 修复」三张并排、**外缘放大 6 倍**看 ——
白描边只有 1~3px，不放大根本看不出来（`attachments/l2d_edge_probe.py` 就是干这个的）。
