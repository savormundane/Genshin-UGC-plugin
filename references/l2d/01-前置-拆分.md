# 01 · 前置：从图集拆到可用的分层

这一步的质量决定后面拟合、动画与边缘处理的上限，所以值得先花点时间定下来。

> ## 我们的选择：**用 PS 之类的手工工具扣**（不是唯一解）
>
> 我们试过写自动拆分脚本（按连通域 + 软边生长），**效果不够好**，最后采用的分层是
> 在 PS 里手工扣出来的。原因是自动拆分解决不了"语义"问题，见 1.2。
> **手工扣 26 层大约半天到一天**，这笔时间在我们这个项目上是回本的。
> 但这是**我们的选择**：如果你的素材规整、或者你有别的分层办法（AI 辅助分层、
> 从画师那里直接拿图层、按绘制顺序反推……），只要满足 1.4 的四条约定，同样可行 ——
> 下面写手工扣的细节，是因为我们只完整验证过这一条路。

产物：一组**同尺寸、已摆好位置、alpha 二值**的 PNG（示例目录 `parts/`）。

---

## 1.1 输入长什么样

源头是 Live2D 风格的**图层图集**：一张大图里平铺着角色的各个零件（头发、脸、眼睛、衣服、腿……），
每个零件的 alpha 都是硬切的。

本例的输入是一张 **1024×512 的 RGBA 图集**（`atlas.png`），拆完得到 **411×600 的 26 层**。

---

## 1.2 拆分判据：什么算"一个零件"

有一条从实践里定出来的规则，**手工扣图时也要照它执行**：

> **任何不连续的都算独立零件 —— 两块内容之间有完全透明的通道，就是两个元件。**

手工扣的时候，这条规则具体化成三个判断：

| 情况 | 判断 |
|---|---|
| 两块之间有一条**全透明的通道**（哪怕只有 1px 宽） | **两个零件**，分别扣 |
| 两块只在**对角相接**（斜着蹭到一点） | 对角相接处是一个全透明角点 → **两个零件** |
| 两块粘在一起、没有透明通道 | 同一个零件，不要硬切 |

### 为什么脚本自动拆不行

我们试过自动拆分：阈值摘"核心"像素 → 4 连通求连通域 → 软边按最近邻生长。
技术上跑得通，但**结果不能用**，原因有两条：

**① 抗锯齿的淡像素会"架桥"。**
直接对 `alpha > 0` 求连通域，两个本该分开的零件会被 alpha 1~8 的极淡像素连成一块 ——
看起来是一个零件。得先把阈值提到 32 才能把这些淡桥排除掉，而 32 这个值本身就得靠试。

**② 真正的障碍是语义，不是连通性。**
人画的时候是按"语义"分层的，而连通域只认"连不连"：

- **左眼白和左眼珠**在某处相接 → 自动拆成一块；但它们必须是两层（变换不同，见 `05`）
- **前发的一缕和旁边一缕**在发梢粘住 → 自动拆成一块；但它们在动画里要分别甩
- 反过来，**一处高光**可能被拆成独立小块，但它其实应该跟脸一起动

这类判断只有人能下。所以我们最后是：
> **自动拆分当"看一眼有哪些区域"的辅助；最终分层手工定**（26 层）。

## 1.3 PS 手工扣图的实操要点

**核心目标**：每个零件是一层，同尺寸画布，内容按原位置摆好，导出时 alpha 尽量干净。

### 建立工作画布

1. 新建与目标展示尺寸一致的文件（本例 **411×600**），把图集里的角色拖进来当底图
2. **底图锁定 + 降低不透明度**（30% 左右）当参考，扣完删掉
3. 每个零件单独一层，**不要用图层组套娃**（导出时要逐层出 PNG）

### 扣图手法

| 手法 | 说明 |
|---|---|
| **钢笔工具**（推荐） | 抠硬边线条最准、边缘最干净；转成选区后填充/加蒙版 |
| 魔棒 / 快速选择 | 快，但**务必关掉「消除锯齿」**，否则边缘会出现半透明像素 |
| 蒙版 + 画笔 | 适合头发丝这类不规则边缘，可以随时补/削 |

**关键：关掉所有抗锯齿/羽化**。图层 alpha 越接近二值，后面越省事
（`06-边缘与画质.md` 里"硬边"那一整节都建立在这个前提上）。

### 层的顺序与命名

- 按"数字小的在上层"命名：`part_0000_xxx.png` 是最上面那层，编号越大越靠下
- **保险做法**：扣的时候按从下往上的顺序建层（先画身体、再衣服、再头发），
  这样图层顺序天然就是对的，命名时倒着编号即可
- 顺序错了不用重扣，改文件名就行

### 导出

1. 隐藏底图，**逐层**导出 PNG（PS 的「导出为」或「快速导出为 PNG」）
2. 所有层必须**同尺寸**（就是画布尺寸），不要"裁到内容"
3. 导出前检查：每层都是 **RGBA + 透明背景**，不是白底

### 导出后自检（一条命令）

> 配套脚本：`attachments/l2d_check_layers.py`
> （本项目实际用的就是"一层一层导出，然后跑一遍脚本确认尺寸/alpha/透明区颜色"）

```
① 所有层尺寸一致              ← 不一致下游坐标全乱
② 中间 alpha 像素数 = 0       ← 有中间值说明混进了抗锯齿
③ 透明区 RGB 记下来           ← 后面拟合放大时它会被卷进边缘（见 02）
④ 层数 + 编号连续性           ← 留意有没有缺号、重号
```

## 1.4 手扣层的四条约定 【约定】【可调】

这四条是**我们定下的规则**，整条流水线依赖它们。**换一套同样可行**，
只要满足右边"真正的要求"那一列。

| # | 我们的做法 | 真正的要求（不能省的） |
|---|---|---|
| ① | 所有层同尺寸（411×600），内容按位置摆好 | 每层的坐标基准**统一且明确**。可以是"同尺寸画布"，也可以是"各自裁紧 + 记录偏移"，只要下游能还原到同一个坐标系 |
| ② | alpha 严格二值（只有 0/255） | **知道自己的 alpha 是什么性质**。二值 → 后面按"硬边"处理；抗锯齿 → 按软边处理，并且要接受边缘会被拟合得更糊 |
| ③ | 文件名编号即层序：数字小的在上 | 绘制顺序**有明确定义且可程序化读取**。用文件名、用清单文件、用目录顺序都行，但**不能靠"碰巧"** |
| ④ | 命名 `part_NNNN_名字.png` | 有一个**稳定 ID** 能把"数据 / rig / 部件表"三边对上 |

下面按我们的做法展开，替换成你自己的规则时逐条对照即可。

### ① 所有层同尺寸、且已摆好位置

```
411 × 600，每层都是整张画布大小，内容在自己该的位置上
```

**为什么选这个**：不需要每层记偏移量，合成就是"按顺序叠"。
代价是文件大（大部分是透明像素），但对这条流水线不影响（拟合只在 alpha>阈值处取样）。

**替代方案**：每层裁到内容外接框 + 记一个偏移量。省空间，但合成/拟合时都要把偏移加回去，
多一处容易出错的地方。两种都行，选一种并保持一致。

### ② alpha 的性质（本项目是二值）

实测：26 个手扣层里**没有任何中间 alpha 值**。

**为什么值得关心**：
- 后面"硬边"那一整套讨论建立在这个前提上（源图本来就是硬边，拟合结果却是抗锯齿的，所以要往硬边拉）
- 如果素材是**抗锯齿**的：那么"往硬边拉"就不再是"还原"，而是"风格化"，两边不一致也没关系，
  但要知道自己在做哪一种
- 透明区的 RGB 记得看一眼 —— 本项目是**纯白 (255,255,255)**，这一点后来成了白描边问题的根因（`06`）

### ③ 层序怎么定（本项目：编号小的在上）

```
part_0000_头发花装饰.png   ← 画在最后（最上面）
part_0001_前发.png
...
part_0026_后飘带.png       ← 画在最先（最下面）
```

本项目绘制顺序 = **编号从大到小**。编号是 `0000`~`0026`，其中 **`0005` 不存在**（人工删掉了一层），
一共 **26 个部件**。

**注意不要用编号范围循环**（`0..26` 会踩到不存在的 0005，也可能漏掉新增的编号）——
**遍历目录里的实际文件**。

### ④ 命名与 ID

`NNNN` 是四位零填充编号，后面的中文/英文名只做人看的标注，**代码只用编号**。
名字里带中文和连字符都无所谓（`part_0008_R-睫毛和眼线.png`）。

替代做法：一个 `parts.json` 列出「ID → 文件 → 绘制顺序」。比文件名更容易扩展（比如一个部件多张图）。

## 1.5 拆完之后立刻要做的三件事

### ① 配一张呼吸 rig（`attachments/l2d_rig.json` 是示例）

每个部件给四个参数，**这是"动作"的起点**，后面所有动画都从这里长出来：

| 字段 | 含义 |
|---|---|
| `w` | 呼吸幅度权重（软物给大：飘带 1.2、前发 1.65；硬物给小：腿 0.22） |
| `delay` | 相位延迟（秒）。**次级运动**的来源：发丝比身体慢半拍 |
| `rot` | 跟随呼吸的旋转幅度（度），绕 `pivot` |
| `pivot` | 该部件的旋转轴心（源图像素坐标）。发丝用发根、手臂用肩点 |
| `group` | 分组名，动画按组给权重（见 `05-动作与骨骼.md`） |

分组的实际取值：`head / bangs / hairBack / tailL / tailR / ribbon / body / armL / armR / legs`。

### ② 确认合成结果

把 26 层按顺序叠起来，和原画对比。这一步能提前发现"层序错了""位置偏了"。

工具：`attachments/l2d_compose_layers.py`（按顺序叠层导出一张对照图，并统计每层露出多少）；
也可以看拼合台（`attachments/l2d_build_assembly.py` 生成的单文件 HTML，
能在浏览器里拖动每层、检查位置与遮挡关系）。

### ③ 量一下"可见面积"

被上层完全盖住的层（本项目的 `part_0020_pantsi` 露出 0px）**不能删**：
角色一动它就会露出来。但拟合预算可以给到最低（留个底就行），因为平时看不见。

## 1.6 规则分成两栏

### 必须满足（不满足就坏）

- 所有层的**坐标基准统一**，下游能还原到同一坐标系。
- 每个部件的**绘制顺序有明确定义且可程序化读取**（不能依赖文件系统的遍历顺序）。
- 一个**稳定 ID** 贯穿「数据 / rig / 部件表」，三边能对上。
- 重新拆图时**不要改变已有 ID 的含义**（改了就等于把所有下游数据作废）。

### 参考实现（可以不同）

| 我们的做法 | 说明 |
|---|---|
| 26 个部件、编号 `0000`~`0026` | 部件数由画风决定；本项目人工按语义分，26 个够用 |
| 同尺寸 411×600 全幅画布 | 也可以裁紧 + 记偏移 |
| 数字小的在上 | 也可以数字大的在上、或用清单文件；**只要一致** |
| alpha 二值 | 抗锯齿素材也能做，只是"硬边"变成"风格化"而不是"还原" |
| `w` / `delay` / `rot` / `pivot` 这套 rig 字段 | 字段名随意，动作用得到就行 |

### 做完立刻量一下（判好坏，不看数字）

| 要保证 | 怎么量 |
|---|---|
| 分层没拆错 | 按顺序合成后与原画对比，边缘无错位、无缺块 |
| 层序对 | 合成结果里该盖住的盖住了（脸不盖头发、眼睛在脸上面） |
| 坐标统一 | 任取一个部件，它的内容在原图坐标系里的位置能算出来且对得上 |
| 被遮住的部件没被删 | 列出"露出 0px"的部件，确认它们仍在数据集里 |

## 1.7 常见错误

| 现象 | 原因 |
|---|---|
| 拼起来角色缺一块 | 自动拆分把语义上分开的部分连成了连通域，或反过来把一个零件拆碎了 |
| 零件之间有条缝 | 拆分时只算了核心像素（alpha>32），把软边丢了 |
| 层序错乱（脸盖住头发之类） | 用了目录遍历顺序，或把"编号小在上"记反了 |
| 拟合出来边缘发虚一圈 | 素材 alpha 不是二值的（被某个工具重新导出过） |
