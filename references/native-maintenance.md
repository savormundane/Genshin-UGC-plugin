# 原生结构维护

能力名：native-maintenance。入口为scripts/native_core.py与qianxing.py native，节点图严格构建使用build schema 2。只读输入，输出新文件；依赖Python标准库和包内节点类型定义，编译另外使用Ayaya。

```text
python scripts/qianxing.py native inspect CURRENT.gil
python scripts/qianxing.py native audit CURRENT.gil
python scripts/qianxing.py native apply CURRENT.gil --spec PATCH.json --out NEW.gil
```

PATCH采用schema=2、base_sha256、allowed_top_level_fields及operations。基底摘要不符、目标重复、保护字段变化或最终类型错误均拒绝输出。operations支持replace_graph、append_graph、rewire、mount、section_from、optimize；图以graph_id定位，替换源以source及可选source_graph_id选择唯一图。replace_graph保留目标图标识和名称。section_from是显式授权的整段替换，不能用它隐藏游戏模板。

需要先审阅变更时使用[原生差异与修改计划](native-changes.md)：native plan在内存执行补丁，绑定外部来源、预期结果和差异摘要；native apply --plan核对同一内容后写新文件。native diff比较已识别语义与完整原始字节变化，未知组件不被当作无变化。produce native.plan及portable复用同一合同。

rewire字段为graph_id、node、input:[kind,index]、source_node及source_port。mount字段为section（4模板／5实例）、entity_id、graph_id及category；目标须有已校准图组件。optimize仅接受内置证明可合并的读取节点类型及明确fanout_cap，不根据调用方自报“纯函数”放行其他节点。

build schema 2沿用现有图配置，新增replace_graphs:[{graph_id,graph_name}]。它在临时基底编译，保留现有挂载引用和无关图正文。struct_bindings:[{graph_name,struct_id}]用于明确只有一种结构体绑定的生成图，将通用拼装／拆分节点绑定到真实声明与端口UID；多结构体图应拆分绑定或使用明确的已有节点定义，不自动猜选。

export_epoch指定新导出GIA路径标签的可重建时间戳，默认0；UID、图ID、文件名和图正文保持。replacement-report保留后端原始标签与规范化标签。此操作只作用于本轮新GIA，原始输入及基底时间字段不改；schema 1仍保持旧导出行为。

graph_ids对新编译图指定ID时，同步更新该图在已校准图库及实体/模板挂载中的引用；允许修改字段必须覆盖实际变化的区段，否则失败，不静默扩宽授权。此处理限于编译器新分配的图，不是任意旧工程ID迁移。含复合依赖的新GIA在构建中执行严格原生审计后才进入GIL对照与交付。

新增声明同时更新10/5/2声明索引；schema 2构建在隔离基底补齐现有声明的真实locator再分配新信号。只扫描信号索引会在信号增多时覆盖结构体帮助节点，不能从“本轮图还能运行”推断未引用声明可被重用。客户端定向信号的新角色也登记索引，保留后续迭代的标识空间。

最终审计读取实际连接和声明，包括隐式输出；未知类型列入unresolved，不能冒充通过。GIA与GIL对照区分字面常量与已连接端口的类型载体。设置自定义变量的隐藏布尔输入4仅在它与原GIA显式触发输入3完全一致时允许新增，读取变量的隐藏布尔输入2仅允许已校准的false默认值；不放行任意新增常量。最终审计同时拒绝触发输入3与镜像输入4的常量冲突。编辑器展开计数和真实执行另验，不将stored_nodes等同于展开数。

scripts/native_ports.py按声明判断端口存在性，不能以实例中出现了某个端口作为其合法依据。内置数据口读取类型表，流程口通过包内语义映射和节点源码的AST声明核对；不执行第三方节点实现。动态声明检查流程、数据及元数据端口和已提供的UID，拒绝重复槽位与声明组不一致。允许声明存在而实例省略的隐式端口；仅记录在输出端的连接也检查远端端口、类型及结构体身份。

拼装列表按原生计数输入限定实际数据口，计数范围0至100；多分支按已编码的分支标签列表限定流程出口。列表取项的序号输入按节点声明补足旧类型表遗漏。结构体修改声明中没有端口描述的编辑选项不占用输入口0；信号名元数据在没有端口描述时使用元数据声明顺序，不与数据口混淆。这些规则来自包内写回实现和校准文件，不推测未校准结构。

审计识别编辑器保存的完整 100 项服务端列表槽位，依据节点家族的具体类型核对类型。存在显式数量时，超出数量的槽位可作为存储记录读取，连接仍受实际数量约束。服务端的实体类型和结算状态端口按原生枚举读取。图注册核对包含图库文件夹与未分类页签。类型冲突在 `native audit` 的 `issues` 中定位至图类别、节点、原生定位器和端口，并给出实际值与采用的契约。未知契约列为 `unresolved`，均会阻止严格写入。

技能图、筛选图与造物状态图的端口按原生类别、节点与内核定位器选择合同。类型编号使用各自的 `ClientVarType` 或 `VarType`。客户端端口表只包含节点和类型数字，依据包内 [native-client-ports.json](../scripts/native-client-ports.json) 的固定来源记录重建，并保留 [MIT 许可证](native-client-ports.LICENSE.txt)。旧模板的特殊端口另有原生描述符、局部变量类型选择或同文件结构声明作为依据。 [上游资料来源](https://github.com/josStorer/genshin-ts/tree/64f10a8da9dad1a8cd79373e94331d8f448676e8)

通用发送/监听信号节点通过常量信号名和本文件信号登记解析实际角色声明；审计使用临时读取视图，不改原始节点字节。声明缺失、角色未登记、名称/引用冲突及非法端口拒绝；通用结构体节点必须绑定实际声明。未知数据口合同与未知流程口合同均列入unresolved。实体按section与entity_id建立身份，区段内重复ID、缺ID和同实体重复图挂载拒绝，模板与实例同号不直接视为重复。

GIA 没有 GIL 信号登记表，`native_signals` 按声明行为、类别及同组引用读取角色，核对角色唯一性、资源依赖、定位器、版本、固定监听输出及参数。旧 GIL 的客户端发送角色也可能只在声明内保存两个同名服务端对端。审计通过登记表、对端定位器、版本和端口描述符核对该关系。

schema 2新导出的GIA中，获取自定义变量节点按类型表及显式输出类型补齐遗漏的具体类型编号；仅处理该节点的标量／列表特化。已有非默认具体类型与输出冲突时拒绝，字典与结构体不通过此规则猜测。build-report的gia_variable_type_bindings记录变化。此生成期适配不修改用户原始GIA，不放宽audit：直接审计具体类型与输出矛盾的文件仍失败。

schema 2构建使用scripts/gia_backend_adapter.py适配隔离后端进程：将已登记的信号事件标题纳入依赖收集（包括复合子图），保留客户端发送声明的固定内核2000。只改变依赖收集视图，不修改GraphModel或vendor文件。新导出GIA缺少实例版本时按实际信号声明补齐，已有冲突版本拒绝；不用于修复用户原文件。compiler-report的gia_backend_adapters、gia_signal_audits和bound_versions记录适配与绑定。含信号声明的最终GIA执行完整原生审计，故障时整个produce不提交。schema 1沿用原导出行为。

显式struct_bindings同时用于新生成的服务端GIA和GIL。scripts/native_gia.py从当前基底读取目标结构体及嵌套类型依赖、服务端帮助声明，按已校准的GIA结构体资源与声明包装加入依赖；新增帮助声明与本轮信号ID冲突时仅重分配新GIA副本的帮助声明ID，报告gia_structure_bindings保留映射。绑定数据口、类型身份和UID后再跨格式比较，拆分节点的源码占位参数不作为实际输入。缺失结构体、身份冲突或未校准客户端图拒绝；原始基底不变，不把此操作当任意工程迁移。信号事件的固定输出“事件源GUID”使用GUID类型，整数标注会被严格审计拒绝。

内置节点的具体类型ID必须属于该节点自身的TypeMappings，不能仅因它是文件中的另一个已知节点或动态声明而放行。用户声明的两份引用必须一致；实例版本和声明版本均按省略值0比较，不能用省略实例版本绕过非零版本要求。没有校准合同的内置元数据端口也列入unresolved，默认严格审计拒绝；显式strict_audit=false仅放宽未解析合同，不放宽已确认错误。

结构体检查不依赖是否有连线或消费者。scripts/native_structures.py核对声明端口、结构体辅助节点目标、实例值载体与结构体登记；同一端口多处身份冲突、未使用声明的悬空引用也失败。结构体正文1/2若同时存在，标识必须一致；各正文独立核对成员序号和类型。已校准的结构体／结构体列表默认值核对描述符、值容器及列表元素的结构体引用，并检查嵌套结构体默认值。值实例的引用ID不当作结构体定义ID；正文默认值可以不同，不要求两份正文逐字节相同。

结构体成员为字典时，分别核对成员声明和默认值描述中的键/值类型与结构体目标；空字典也检查目标存在性。默认值的37/503、37/504是键/值类型，描述符子类型504才是值结构体ID。非空默认值检查并行键值列表及已校准键值对载体的类型、数量和身份，递归检查其中的结构体、结构体列表和嵌套字典引用。字典键值对自身的局部载体身份（原始字符串/布尔样本为64）不是全局结构体定义ID。支持后端的空bytes默认值与并行列表表示；未知身份列入unresolved，不能静默放行。此检查不等于完整字典执行、所有标量值语义或任意编码形态支持。

局内存档模板和槽位即使没有挂载任何图，也核对各自命名空间中的重复标识及槽位的结构体引用。仅按已校准的结构体槽位描述解析，未知槽位种类列入unresolved。诊断包含声明、图/节点、正文/成员或模板/槽位位置；检查不修改输入字节。

[自定义变量读取](native-variables.md)分别处理模板默认值与实例覆盖，核对重复名称、类型/默认值及深层结构体引用，并将声明、继承/覆盖和结构体消费者接入工程索引。动态创建与变量访问仍需按工程合同分析，不能将未声明变量一律视作悬空，也不能将声明索引当成完整访问索引。

GIA结构体资源从unit/22/1读取到同一结构体模型，外层资源身份必须为class=1、type=15、Which=29，且ID与正文相符；缺失包装、错误身份及重复定义拒绝。原始结构体GIA携带的客户端拼装/拆分辅助声明，在20001、20002、20007类别中分别引用内核1060/1061，按已校准类别与行为核对，不机械要求shell/kernel定位器相同。其它内核、类别或定位器变化仍拒绝。结构体列表端口既可在104直接携带身份，也可通过102/1的元素类型描述携带身份；两处冲突或元素不是结构体均失败。inspect、连线和复合接口检查共用这项身份读取。

普通图与复合内部图分别读取：GIL对应10/1和10/4，GIA按图定位器kind区分；inspect增加composite_graphs，普通graphs保持普通图范围，instances中的graph_kind区分同号普通/复合图节点。复合图内部节点进入同样的端口、连接、版本与结构体检查，不作为模型独立事件入口。声明signature的两份类型引用按身份核对；校准的客户端发送角色允许自身shell与内核2000的特定引用关系，其他不一致或缺失失败。空的非复合图引用是已校准占位，不当作悬空复合图。

复合声明必须指向实际内部图。外部映射核对声明槽位、内部节点、方向、端口和类型。数据输出须有唯一映射。旧版「修改结构体」调用以声明端口 UID 核对已存端口，可在相邻写入开关的 UID 和内核索引均匹配时解析已校准的复合输入偏移。其他无法确认的索引和缺失的声明、图库或 GIA 依赖仍阻止严格写入。

apply的图操作可显式给graph_kind:composite，默认ordinary；同号普通图与复合图互不选中。替换保留目标定位器与名称的存在状态；依赖声明不隐式复制。复合图优化会同步映射中的内部节点引用。编译回读分别比较普通图和复合依赖；两个后端独立分配复合ID与端口UID，因此跨格式按唯一声明名称、类型接口、节点/连线、常量和映射核对，各文件内部身份关系独立审计。存储节点预算包含去重后的复合内部节点，无关既有复合图正文保持原字节。此支持不表示原生模型已实现复合调用执行。

build schema 2的required_mounts使用graph_name、entity_id及可选section（4模板／5实例）。未指定section时实体必须在这两个区段中唯一；同名图或跨区段同号应明确消歧，不能用模板挂载满足实例要求。当前检查仍只覆盖校准的图组件与已支持节点，其他元数据和跨资源引用需要按实际合同继续扩展。

修改字段、ID和结构体绑定必须来自当前文件或明确新建配置。原生字段规则和校准定义保留来源；不恢复完整游戏模板。验收覆盖两组图标识、错接结构体列表、保护字段、现有图替换及挂载，分别记录静态、编译回读和宿主状态。

中性配置可分别选择一个整数读图和一个结构体列表读图，先inspect取得graph_id与基底摘要，再只允许字段10并执行rewire；追加消费者后会重新核对实际输出类型和结构体身份。replace_graph只替换图正文，不隐式携带依赖；新增声明须通过明确的section_from或完整build资源阶段处理。挂载还需允许实例／模板字段及图库字段6。错误摘要、重复ID、错接端口、动态端口UID不符或缺挂载均拒绝输出。optimize显式给出纯读取类型和fanout_cap，现有读表达式已超预算同样失败；默认不开启合并。

[节点图变量检查](native-graph-variables.md)在最终GIL/GIA图正文核对声明与VarBase默认值、列表/字典子类型及显式结构体依赖；不套用实体变量编码，不把读取通过当作运行模型通过。

数据输入按图内节点及端口检查唯一提供端：连接可记录在输入端、输出端或两端，同一连线的双端记录视为一个来源。不同节点或同一节点的不同输出连接同一数据输入时返回multiple data input providers，直接audit、apply及produce均拒绝；strict=False不豁免已确认的冲突。输出扇出仍允许，不将这项规则套用到执行线汇合，也不把静态唯一来源证明当作运行顺序证明。

受限NativeModel采用相同的连线方向归一规则，读取最终产物时建立图内数据输入来源索引，不改原文件。输出端独有记录、双端镜像和隐式输入口均可取值；连线优先于输入口残留默认值。查询节点实参集合包含隐式已连接输入，多个不同来源及悬空/错误方向在模型初始化时拒绝。未知节点执行仍失败，不扩大受限模型支持节点范围。
