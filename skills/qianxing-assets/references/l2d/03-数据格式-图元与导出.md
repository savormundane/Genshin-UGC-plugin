# 03 · 数据格式：图元、导出、三套坐标系

这一节是**写代码时的对照表**。三种图元、一个 JSON、一个紧凑文本行、三套坐标。

---

## 3.1 shapes.json（拟合的原始产物）

```json
{
  "format": "geimg-shapes",
  "format_version": 1,
  "space": "source_image_pixels",
  "count": 1700,
  "shapes": [
    {"t":"circle",  "x":110.193, "y":77.58,  "r":26.353,               "rgba":[212,211,188,252]},
    {"t":"ellipse", "x":132.98,  "y":148.663,"rx":21.347,"ry":21.347,"a":2.351687,"rgba":[210,217,197,252]}
  ]
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `t` | `"circle"` / `"ellipse"` / `"line"` | 图元类型 |
| `x`, `y` | 源图像素 | **圆心**（不是左上角） |
| `r` | 源图像素 | 圆的半径（只有 `circle` 有） |
| `rx`, `ry` | 源图像素 | 半轴（`ellipse` / `line`） |
| `a` | **弧度** | 旋转角（`ellipse`/`line`）。**注意是弧度不是度** |
| `rgba` | 0~255 ×4 | 颜色 + 不透明度 |

**数组顺序就是绘制顺序**，下标 0 在最底层。

三个必须记住的细节：

1. **`a` 是弧度**。本项目在解析时踩过：以为是度数，算出来的包围盒完全不对。
2. **`r/rx/ry` 都是半径/半轴**，不是直径。导出成控件的尺寸时要 **×2**。
3. **`line` 也是椭圆**，只是 `ry` 很小（渲染成细长椭圆即可，不需要单独的线段路径）。

## 3.2 Lua 紧凑行（本项目导出用的格式）

```
"c|110.19|77.58|52.71|52.71|0.00|D4D3BCFC"
 t    x      y      w     h    rot    RRGGBBAA
```

| 位置 | 含义 |
|---|---|
| `t` | `c`=circle / `e`=ellipse / `l`=line（单字符，省体积） |
| `x`,`y` | 源图像素，圆心 |
| `w`,`h` | **直径 = 半径×2** |
| `rot` | 角度（**度**），且**已经取过负** |
| 颜色 | 大写十六进制 `RRGGBBAA` |

### 为什么 rot 要取负

- 源图坐标系是 **Y 向下**（图像惯例）
- 画布坐标系是 **Y 向上**（游戏 UI 惯例）
- 同一个旋转，在 Y 翻转后方向相反 → 导出时取负，Lua 侧就不用再想这件事

对应代码：`rot = -math.degrees(s["a"])`。

**约定**：紧凑行一旦进了 Lua，里面的 `rot` 就是**最终值**，运行时不要再取负。

## 3.3 三套坐标系（最容易出错的地方）

| 名称 | 原点 | Y 方向 | 谁在用 |
|---|---|---|---|
| **源图像素空间** | 左上 | 向下 | `shapes.json`、图层 PNG、rig |
| **画布空间** | **左下** | 向上 | `game.GetCursorUIPos()`、`GetUICanvasSize()` |
| **控件空间** | **容器中心** | 向上 | `SetAnchoredPosition` / `anchoredPositionX/Y` |

### 从源图像素到控件位置的完整换算

```lua
-- 常量（构建时算好写进 CFG）
scale      = min(1120 / 411, 630 / 600) = 1.050000   -- 目标展示尺寸 / 源图尺寸
offsetX    = 800 - 411 * scale / 2      = 584.225    -- 这里 800 = 画布宽/2
offsetY    = 450 - 600 * scale / 2      = 135.000
sourceHeight = 600

-- 每帧/每个图元
local function place(c, sx, sy)          -- sx,sy = 源图像素
  c:SetAnchoredPosition(
    CFG.offsetX + sx * CFG.scale - CX,                     -- CX = 实际画布宽/2
    CFG.offsetY + (CFG.sourceHeight - sy) * CFG.scale - CY -- CY = 实际画布高/2
  )
end
```

三个要点：

1. `(sourceHeight - sy)` 就是 **Y 翻转**。
2. **末尾减 `CX, CY`** 是把"画布左下原点"换成"容器中心原点"。**漏掉这一步，整个角色会窜到右上角**——
   本项目实际踩过：修复前 X 范围 620~950、Y 范围 155~740（全跑到半画布外），修复后 -180~150 / -297~293。
3. `CX, CY` 要**运行时取**，不要写死：

```lua
local w, h = CFG.canvasW or 1600, CFG.canvasH or 900
if game.GetUICanvasSize ~= nil then
  local gw, gh = game.GetUICanvasSize()
  if gw ~= nil and gw > 0 and gh ~= nil and gh > 0 then w, h = gw, gh end
end
CX, CY = w * 0.5, h * 0.5
```

⚠️ 未验证：`GetUICanvasSize` 在真机返回的是不是"设计分辨率"。本项目按 1600×900 硬编码做回退，
实机如果不同尺寸，只要它是同一个坐标系就仍然正确。

### 光标坐标

`game.GetCursorUIPos()` 返回的是**画布左下原点**的坐标。做视点跟随时要：

```lua
local px, py = game.GetCursorUIPos()
local nx = (px - CX) / CX      -- 归一化到 [-1, 1]
local ny = (py - CY) / CY      -- 注意 ny > 0 = 光标在角色**上方**
```

**`ny > 0` 表示"上方"**（因为 Y 向上）。而源图 Y 向下，
所以让虹膜向上看时要 **取负**：`irisDy_offset = -ny * 幅度`。

本项目早期把上下做反过，就是漏了这一步。

## 3.4 部件表（构建时生成）

部件把连续的下标区间映射到一组动画参数：

```lua
local PARTS = {
  { n=26, f=1,    t=300,  px=160, py=300, w=1.2,  delay=0.26, rot=3.6,  g=6 },
  --  ↑编号  ↑首个图元 ↑末个图元 ↑旋转轴心        ↑呼吸权重 ↑延迟    ↑旋转  ↑组
  { n=9,  f=6358, t=6654, px=207, py=300, w=1.55, delay=0.04, rot=0,    g=1,
    role="iris", side="eyeL", geo={top=213.6, bot=263.3, lidCy=225.8, cy=238.45} },
}
local GN = {"head","bangs","hairBack","tailL","tailR","ribbon","body","armL","armR","legs"}
```

- `f`/`t` 是 **1-based 闭区间**，`f` 对应 RAW 数组里第一个图元。
- `g` 是组索引，**指向上面的 `GN` 表，1-based**。
  ⚠️ 构建脚本如果生成 0-based 索引，会整体错位一位（本项目踩过：头拿到 nil、腿继承了别人的权重）。
- `role`/`side`/`geo` 只给需要特殊处理的部件（眼、眉、嘴），见 `05`。

## 3.5 规则分成两栏

### 必须满足（不满足就坏）

- 解析 `shapes.json` 时：**`a` 是弧度**、**`r` 是半径**（不是直径）、**数组顺序即绘制顺序**
  （这三条是 GEIMG 输出的既有约定，不是你我能选的）。
- **任何屏幕坐标计算，先确认现在是哪套坐标系**；跨坐标系**必须显式转换**。
- **同一份数据在整个链路里必须保持同一个坐标空间**（中途换空间就要到处改换算）。
- 场景里的容器中心**要运行时取**（`game.GetUICanvasSize()`），不要写死 ——
  写死了换分辨率就错位。
- 部件表的组索引要与代码里的组名表**同样的起始编号**（我们用 1-based；换 0-based 就处处 0-based）。
- 图元数据**内联在 Lua 里**（沙箱禁了 `io.*`）——这一条是被运行环境逼的，没得选。

### 参考实现（可以不同）

| 我们的做法 | 可以这样 |
|---|---|
| 紧凑行 `t\|x\|y\|w\|h\|rot\|RRGGBBAA` | 任何格式；也可以直接嵌 JSON（更大、更慢，但更好读） |
| 导出时把角度取负、运行时不再翻 | 也可以存原始角度，运行时翻 —— **只要只翻一次** |
| 画布 1600×900、缩放 1.05、偏移 584/135 | 任意展示尺寸；按 3.3 的公式自己算 |
| 部件表用 `f`/`t` 区间 + `g` 组号 | 用数组引用、用名字查表都行 |
| 部件表里放 `role`/`side`/`geo` | 也可以另外放一张"特殊部件表"；`geo` 的字段名随你 |

### 验收：怎么确认坐标这套没搞错

| 要保证 | 怎么量 |
|---|---|
| 整体不出画布 | 所有控件位置落在 ±半画布内（本项目越界 0 个） |
| 上下方向对 | 把光标移到画布**上方**，头/眼应向上（不是向下） |
| 尺寸对 | 抽一个图元，算它应占的屏幕像素数，和实际 `sizeDelta` 比 |
| 旋转方向对 | 让一个部件转 +10°，看它在屏幕上是不是你预期的方向 |
| 层序对 | 眼睛应该盖在脸上面、头发盖在脸的一部分上面 |

## 3.6 常见错误

| 现象 | 原因 |
|---|---|
| 整个角色窜到窗口右上角 | 忘了减半画布（画布空间 vs 控件空间） |
| 角色位置对但上下颠倒 | Y 翻转漏了 / 做了两次 |
| 图元尺寸是预期的一半 | 把半径当直径用了 |
| 椭圆方向不对 | `a` 当成了度数 |
| 层序整体错一位 | 组索引 0-based vs 1-based |
