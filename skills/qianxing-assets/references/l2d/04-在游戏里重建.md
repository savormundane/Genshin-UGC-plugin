# 04 · 在游戏里重建：控件、层序、加载、性能

目标：把图元数据变成游戏里的角色。这一节只讲**怎么把控件建出来并驱动**，动作设计见 `05`。

---

## 4.1 一个图元 = 一个图片控件

> **重要**：这一节讲的是"平铺"结构（现在跑通的版本）。
> 更好的做法是把同一骨骼的图元挂到**父容器**下、只对容器做动画 ——
> 每帧写入能从 866/3286 次降到几十次，见 **`11-层级与骨骼-父容器.md`**。
> 下面这套仍然是基础（容器里装的还是这些控件），先看懂这里再看 11。

```lua
local c = game.InstantiateClientUIControl(CFG.imagePrefabId, root)
c:SetAnchorMin(0.5, 0.5)          -- 锚点收紧到中心，位置才好算
c:SetAnchorMax(0.5, 0.5)
c:SetPivot(0.5, 0.5)
place(c, d.x, d.y)                -- 见 03：源图像素 → 控件空间（含减半画布）
c:SetSizeDelta(d.w * CFG.scale, d.h * CFG.scale)
if d.rd ~= 0 then c:SetLocalRotation(0, 0, d.rd) end
c:SetImage(Enum.ImageSource.StaticReference, CFG.circleAssetId)  -- 固定圆贴图
c.imageType = Enum.ImageType.Stretch
c.imageColor = Color.FromRGBA(d.r, d.g, d.b, d.a)
c:SetVisible(true)
c:SetSiblingIndex(index - 1)      -- 层序：见 4.3
```

要点：

| 项 | 说明 |
|---|---|
| 圆贴图 | `circleAssetId = 100002`（固定可用的那张）。所有图元共用它，靠 `imageColor` 染色 |
| `ImageType.Stretch` | 必须设，否则圆贴图不跟着 `sizeDelta` 拉伸 |
| 透明度 | 基类**没有** `alpha`/`opacity` 字段，只能用 `imageColor` 的第四通道 |
| 旋转 | `SetLocalRotation(0, 0, 度)`，绕 pivot |
| 圆形 | 圆贴图按 `sizeDelta` 拉伸成椭圆，所以 `w ≠ h` 就是椭圆——**不需要不同的贴图** |

### ⚠️ 边缘硬度取决于这张圆贴图

API 里图片控件有 `enableSoftEdge` / `softEdgeMode` / `softEdgeWidthX/Y` / `horizontalSoftRange` /
`verticalSoftRange`。本项目**没有设置**它们，实机观感取决于该 prefab 的默认值。

如果实机边缘比预期软（源图是硬边，预期是硬边），第一件事就是试 `c.enableSoftEdge = false`。
⚠️ 未验证：默认值是什么、改了会不会影响性能。

## 4.2 容器：先确认找得到，再往里塞

```lua
local function ensureRoot()
  if root ~= nil and root.alive then return true end
  -- 优先用有文档保证的按名查找
  if CFG.containerName ~= nil and CFG.containerName ~= "" and game.FindClientUIRoot ~= nil then
    local r = game.FindClientUIRoot(CFG.containerName)
    if r ~= nil then root = r; return true end
  end
  -- 回退：从脚本宿主往上找同名祖先
  local node = script.object
  if node == nil then return false end
  local p, guard = node, 0
  while p ~= nil and p.name ~= CFG.containerName and guard < 32 do
    p = p.parent; guard = guard + 1          -- guard 防 parent 成环
  end
  if p == nil then return false end
  root = p
  return true
end
```

### 血泪教训：容器可能晚于 `OnStart` 就绪

`InstantiateClientUIControl(prefab, nil)` 是**静默失败**（不报错，返回 nil）。
本项目最初的写法是在 `OnStart` 里直接建 UI：

```lua
-- ✗ 错：root 还是 nil
if UIBuild ~= nil then UIBuild() end
```

结果：UI 控件 0 个、按键监听 0 个（因为监听挂在控件上），而**日志里只说了一句"UI 未建"**。
正确写法：

```lua
-- OnStart：能建就建，不能建就留给 OnUpdate
uiBuilt = false
if ensureRoot() and UIBuild ~= nil then UIBuild(); uiBuilt = true end

-- OnUpdate：容器就绪后补建（只建一次）
if not uiBuilt and UIBuild ~= nil then UIBuild(); uiBuilt = true end
```

同类问题：**找不到容器就不要静默空转**。本项目做到"连续 60 帧找不到就停掉逐帧回调并打日志"，
否则在游戏里表现为"脚本没反应"，而错误只在 `ErrorLog.txt` 里。

## 4.3 层序：`SetSiblingIndex` 与"铺完再重排"

基类**没有 `zIndex`**，层序 = 同级索引。

```lua
c:SetSiblingIndex(index - 1)      -- 图元按数据顺序
```

两个坑：

1. **`SetSiblingIndex` 会返回 boolean 且"受父控件子控件数量限制"**——失败就是层序静默错乱。
   必须检查返回值并出声（本项目 `warnOnce`）。
2. 有 UI 层时，等**角色铺完之后**统一重排一次，顺序是「背景 → 角色 → UI」：

```lua
local z = 0
put(UI.bg)                 -- 背景最底
for i = 1, n do pool[i]:SetSiblingIndex(z); z = z + 1 end   -- 角色
put(UI.fg)                 -- UI 压在最上
```

## 4.4 加载：分帧铺（一帧建一万个会卡住那一帧）

```lua
if not done then
  local budget = CFG.budgetPerFrame        -- 本项目 40
  while cursor <= total and budget > 0 do
    local c = spawn(shapes[cursor], cursor)
    if c ~= nil then pool[cursor] = c end
    cursor = cursor + 1
    budget = budget - 1
  end
  if cursor > total then done = true; if UIReindex then UIReindex() end end
  return                                    -- 铺完之前不驱动动画
end
```

- 9941 个控件、每帧 40 个 → **约 249 帧铺完**
- 「铺完之前不驱动动画」很重要：否则会看到"部分图元在动"的残影
- 跳跃这类动作要判断 `done`：没铺完不受理（见 `05`）

## 4.5 逐帧回调：默认是关的，必须自己开

```lua
-- 旧文档写的 EnableTick 已经改名，实机是 EnableUpdate
local function startTick()
  if script.EnableUpdate ~= nil then script:EnableUpdate(true); return true
  elseif script.EnableTick ~= nil then script:EnableTick(true); return true end
  return false
end
```

**脚本的 update 开关默认关闭**：不显式打开，`OnUpdate` 一帧都不会被调用 ——
图元铺不出来、动画更不会动。本项目第一次上真机就是这个症状（用户反馈"忘记开 EnableUpdate 了"）。

同时保留 `EnableTick` 回退（老运行时），并在 `OnDestroy` 里关掉。

## 4.6 性能：每帧写多少次属性（这一环的主要代价）

10030 个图元每帧全写 = **60 万次属性写入/秒**。指南里那句
"循环调用……会导致进关加载变久或卡死，且日志无法正常报告"说的就是这个量级。

### 四道闸（按收益排序，都是可选手段）

目标只有一个：**每帧写入次数要明显低于"图元数 × 帧率"**。下面四条是我们用的办法，
也可以只用其中一两条、或用别的（比如把静态区域合并成一张贴图）。

| 手段 | 做法 | 实测效果 |
|---|---|---|
| ① **降频** | `updateStride = 2` → 30Hz 更新 | 图元 >4000 时默认打开，写入次数直接减半 |
| ② **视点 epsilon 闸门** | 鼠标没动 → 骨骼场贡献不变 → 相关部件整帧不写 | 空转时 3286 → **866** 次/帧 |
| ③ **逐图元写入缓存** | 与上次写下的位置差 < `posEps`(0.35 源像素) 就不调 API | 亚像素位移不计；腿那种小权重部件整段被冻住 |
| ④ **部件级跳过** | 部件总位移 < `skipBelow`(0.5px) 且无表情需求 → 整块跳过 | 省下小位移部件 |

### 实测负载（9941 个控件，`updateStride=2`）

| 状态 | 写入/帧 | 写入/秒 |
|---|---|---|
| 鼠标不动（只剩呼吸） | 866 | 52k |
| 鼠标移动（骨骼场 + 呼吸） | 3286 | 197k |
| **不做任何跳过的全量** | 9941 | 596k |

### 还要说清楚的两件事

1. 这些优化压掉的是**每帧属性写入**。**进关卡时的首次创建成本仍然存在**
   （9941 个控件分帧创建，约 249 帧）。
2. 真机实际开销必须在真机上测。本项目上面的数字是**用桩函数跑出来的**（lupa），
   不含引擎的实际渲染与布局开销。

### 想同时降静态成本

只能走"**烘一张整身贴图 + 条带位移**"：静止姿态用几个控件（贴图切片）表达，
动起来只挪条带。这条路需要"已导入的贴图资源 + RenderTexture API"，
本项目尚未验证这类资源是否可用。

## 4.7 规则分成两栏

### 必须满足（这几条是环境事实，违反了就坏）

- **每个图元一个控件**，用圆贴图 + `ImageType.Stretch` 拉伸来表达圆/椭圆与旋转。
- 透明度和层序**没有专门字段**：只能走 `imageColor` / `SetSiblingIndex`。
- **`script:EnableUpdate(true)` 必须自己调**（默认关闭），并保留 `EnableTick` 回退。
- **建控件/建 UI 前确认容器已就绪**；`InstantiateClientUIControl(id, nil)` **静默失败**。
- **`SetSiblingIndex` 的返回值要检查**（失败 = 层序静默错乱）。
- 找不到容器**不要空转**：连续 N 帧失败就停掉回调并打日志。
- **每帧写入量要与图元数量级匹配**（9941 个控件每帧全写 = 596k 次/秒，在我们的机器上
  足以拖慢进关；你的机器可能更宽裕，但量级关系不会变）。

### 参考实现（可以不同）

| 我们的做法 | 可以这样 |
|---|---|
| `budgetPerFrame = 40`（9941 个 → 约 249 帧铺完） | 按你的目标加载时长定：想 1 秒铺完就调大 |
| `updateStride = 2`（图元 > 4000 时自动开） | 1/2/3 都行；先试 2，卡再往上加 |
| `posEps = 0.35` 源像素 | 0.2~0.5 之间；越小越精确、写入越多 |
| `skipBelow = 0.5` 源像素 | 同上 |
| `gazeEps = 0.004` | 视点抖动容忍度；越大越省 |
| 圆贴图 `100002`、prefab ID `1073741850/51/49` | 你自己的资源 ID 与模板 ID（**换场景必须改**） |
| 容器名 `GEIMG_Canvas` | 任意，和场景里一致即可 |
| 铺完再重排层序「背景→角色→UI」 | 也可以一开始就插到正确位置（但要保证角色整体在 UI 之下） |

### 验收：怎么确认"接进游戏"这件事做对了

| 要保证 | 怎么量 |
|---|---|
| 能显示 | 铺完后控件数 = 图元数；坐标不越界 |
| 会动 | 静置能看到呼吸；`frames` 在增长 |
| 层序对 | 背景在最后、UI 在最前、角色在中间 |
| 不卡 | 打印每帧写入次数，明显低于"图元数 × 帧率" |
| 不静默失败 | 日志里有：画布尺寸 / 容器中心 / 图元数 / 铺完 / 层序重排 / UI 控件数 / 按键绑定结果 |

## 4.8 常见错误

| 现象 | 原因 |
|---|---|
| 角色窜到窗口一角 | 忘了减半画布（`03` 有完整换算） |
| 一帧都不跑 / 什么都没显示 | 没调 `script:EnableUpdate(true)` |
| UI 一个都没建出来 | `root` 还没就绪就 `UIBuild()`；或 prefab ID 是 0 |
| 层序错乱 | `SetSiblingIndex` 失败没检查；或没做"背景→角色→UI"重排 |
| 进关卡死 / 加载很久 | 一次性建上万个控件；或每帧全量写属性 |
| 圆变成方形 | 忘了 `imageType = ImageType.Stretch` |
