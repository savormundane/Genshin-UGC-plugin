# 典型使用场景

以下示例是**向 Agent 提交任务的参考输入**，不是已经生成或实机验证的样例资产。执行前应提供实际工程路径与目标平台版本。

## 工程与资源诊断

> 读取这个千星奇域工程，先做只读诊断。检查实体、组件、资源引用和版本兼容；列出问题、证据及建议，不要把未确认字段写入工程。

相关能力：Editor、共享诊断。参考 [工程检查](../references/project-diagnosis.md)。

## 节点图和 GIL

> 根据下面的玩法规则给出节点图及端口设计，核对执行流和数据流；再基于指定 GIL 做安全修改，保留未知字段，并提供修改前后差异与回读结果。

相关能力：Graph Code、GIL。参考 [节点图](../references/graph-authoring.md)和[GIL 工具](../references/gil-tooling.md)。

## Client Lua 控件

> 基于当前能确认的客户端 API 编写控件逻辑，说明生命周期、输入处理与参数边界。交付 Lua 文件，并把静态验证和宿主未验证部分分开报告。

相关能力：Client Lua。参考 [客户端检查](../references/client-check.md)。

## 图像与图元素材

> 检查输入 PNG 的尺寸、格式与可转换性，评估图元成本、颜色和几何限制；优先提供预览和检查结果，说明导入游戏仍需人工验证的部分。

相关能力：Assets。参考 [素材检查](../references/asset-inspection.md)。

## 建议保留的交付证据

让 Agent 明确给出输入版本、文件清单、可复现检查命令、运行结果及尚未验证的事项；不要将“软件模拟通过”写成“游戏内通过”。
