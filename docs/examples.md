# 使用示例

以下示例覆盖五个核心领域。把工程路径、目标平台版本和需求告诉助手，对应 Skill 可引导助手查资料、校验输入和保护原文件。请检查它实际执行了哪些步骤，并区分本地检查与游戏内验证。

## 1. 排查现有工程（Editor）

**场景**：接手旧地图，或者在导入编辑器报错前想先做一次全盘只读体检。

> “先只读扫描项目里的 `level.gil`，检查实体、模板、组件配置和资源引用，把断链和不符合当前平台版本的地方列出来。”

* **本地会做什么**：读取可识别的工程对象，按已有平台规则核对组件和资源引用，输出只读诊断。
* **产出物**：问题清单、涉及的对象/资源 ID 及对应规则依据。
* **进编辑器后核对**：若报告中标出未收录的自定义资源或新版字段，需在编辑器中人工复核。
* **底层参考**：[工程只读诊断](../references/project-diagnosis.md)

## 2. 写节点图并导出（Graph Code）

**场景**：实现一套玩法逻辑，想先在本地把节点定义、端口类型和数据流跑通再导入编辑器。

> “给双人抢分玩法写一套服务端节点图：开局 60 秒倒计时、碰触加分、时间到结算。检查完端口类型和数据流后导出 `.gia`。”

* **本地会做什么**：按 `server` 作用域查询真实节点定义，编写 Graph Code，调用离线工具链检查语法、端口与数据流并导出。
* **产出物**：Graph Code 源码、静态检查报告和待导入验证的 `.gia`（或挂载后的新 `.gil` 副本）。
* **进编辑器后核对**：导入后检查节点布局、变量初值以及多人联机实机表现。
* **底层参考**：[节点设计与连接](../references/graph-authoring.md)

## 3. 编写客户端控件 Lua（Client Lua）

**场景**：写带交互、倒计时或动画的 HUD 脚本，避免 AI 编造引擎里并不存在的控件 API。

> “查一下 `game.GetUICanvasSize` 和当前可用的按钮回调 API，帮我写一个带倒计时和点击反馈的 HUD Lua 脚本，顺便跑一遍语法和 API 检查。”

* **本地会做什么**：从客户端 API 正文核对接口签名与参数边界，生成 Lua 5.3 脚本，并用本地工具检查语法。按需启用已知 API 检查和软件模拟。
* **产出物**：待挂载验证的 `.lua` 文件（多文件工程附带装配映射表，方便回溯报错行号）及检查报告。
* **进编辑器后核对**：控件实际挂载路径、不同分辨率下的命中框，以及 PC/移动端输入手感。
* **底层参考**：[最终 Lua 检查](../references/client-check.md)

## 4. 对比和局部修改 GIL（GIL）

**场景**：只想替换一个内嵌脚本或比对两版地图差异，最怕误伤原文件里的其他字段。

> “对比 `old.gil` 和 `new.gil` 的差异；再把 `hud.lua` 替换进 `old.gil` 的指定脚本映射，另存成新文件并回读核对。”

* **本地会做什么**：绑定输入文件摘要，先输出语义差异或修改计划，在已支持的容器格式中只修改定位到的目标，保留未改数据，写出副本后回读核对。
* **产出物**：差异报告、新 `.gil` 副本与回读结果；原始文件不会被覆盖。
* **进编辑器后核对**：在千星奇域编辑器中打开新文件并保存一次，确认宿主解析正常。
* **底层参考**：[容器检查与精确替换](../references/gil-tooling.md)

## 5. 图片拟合转图元（Assets）

**场景**：把 PNG 图标或立绘转成千星可用的图元/Lua 数据，同时把控件数压进预算。

> “先检查项目里的 `icon.png` 尺寸和透明度，按 200 个矩形预算拟合成图元，先给我一张本地预览图和误差/字节数汇总。”

* **本地会做什么**：解码前先校验 262,144 像素上限，按预算运行确定性拟合，输出图元数据、`data.lua` 和软件重建预览图（支持保存检查点中断续算）。
* **产出物**：`preview.png`、`primitives.json`、`asset.json`、`data.lua`（按需导出 `.gia`）及预算与误差报告。
* **进编辑器后核对**：软件预览只反映几何和颜色重建结果，进游戏后还需核对图层遮挡、透明边缘和真实帧率开销。
* **底层参考**：[通用拟合与分层续算](../references/asset-fit.md) · [素材检查](../references/asset-inspection.md)
