# 使用示例

从你手上已有的东西选择一个任务。第一次使用、还没有工程时，先看[入门示例](getting-started.md)；术语不熟悉时查[术语表](glossary.md)。

把输入文件放入安装时选择的项目目录，告诉助手目标千星奇域版本、想改变的行为和预期产物。报告与生成文件保存在独立输出目录。

## 工程检查

**场景。** 接手旧地图，想查一个模板挂载了哪些节点图。

> 只读检查工程目录里的 `level.gil`。按当前文件的对象 ID 列出模板、实例和节点图的挂载关系。把识别不了的引用标出来。

`project inspect` 返回已识别的对象、引用和检查范围。拿到结果后，可针对具体对象继续查消费者。平台规则核对需要明确目标版本、模式和配置输入。[工程索引](../references/project-index.md) · [平台规则](../references/platform-profiles.md)

**适合继续问：** “这个模板被哪些实例使用？”“哪项引用是工具尚未识别的？”不用一开始就修改整张地图。

## 编写节点图

**场景。** 玩家进入触发区域时要更新一个关卡变量。

> 先查服务端进入区域事件和变量写入节点的准确端口。用工程里的区域和变量身份写 Graph Code，编译为新的 `.gia`。需要我补充工程对象时，请先列出缺项。

拿到 Graph Code、编译检查结果和产物后，在千星奇域编辑器里导入并核对挂载与事件来源，再试一次进入区域。[节点设计与连接](../references/graph-authoring.md)

**需要提供：** 区域、目标实体和变量的实际身份。缺少这些输入时，助手可以先完成节点设计，补齐身份后再生成可挂载产物。

## 编写客户端 Lua

**场景。** 让一个已挂载控件在收到工程现有信号后更新文本。

> 从现有 Lua 脚本确认控件和信号的写法。查对应的客户端 API，再修改脚本并运行语法检查。遇到项目里找不到的信号字段，先列出来。

产物包括待挂载的 Lua 和检查结果。提供绑定到脚本内容的 API 合同时，可同时检查已声明调用与引用。导入后核对控件挂载和实际信号。[最终 Lua 检查](../references/client-check.md)

**需要提供：** 现有控件层级、脚本入口和信号字段；只有界面描述时，先让助手列出必要绑定。插件不会凭空知道工程里的控件 ID。

## 局部修改 GIL

**场景。** 调整一个已存在的整数型模板默认值。

> 找出 `level.gil` 中机关的 `ActivationDelay` 参数，确认它来自哪个模板、哪些实例继承该值。把模板默认值调到 12，先展示修改计划，等我确认后另存并回读。

适用于已校准的标量默认值和选定的定时器序列等操作。模板和实例覆盖分别选择。应用计划时保留原始 GIL。[原生局部编辑](../references/native-changes.md#局部编辑)

源码版可用 `project_inspect` 的 `selector` 查看依赖和引用者。审阅时核对实际变更和保护范围。应用后回读前后的值、输出文件及摘要。正式包 4.1.0 可用补丁文件和 CLI 执行同一原生操作。[MCP 调用顺序](../references/local-mcp.md#审阅并另存已有工程) · [CLI 修改计划](../references/native-changes.md)

## 图片转图元

**场景。** 把两层 PNG 转成可在客户端叠放的图元。

> 用文件 `shadow.png` 和 `badge.png` 建立两层素材清单，先检查尺寸和透明度。按我给的总矩形预算做拟合，并交付每层误差、实际矩形数、预览和 Lua 数据。

`assets fit` 支持显式分层和检查点续算，每层输入上限为 262,144 像素。只需要固定网格的矩形或富文本时可先用 `assets generate`。软件预览供核对颜色和几何，实际遮挡及性能在游戏内检查。[内置素材生成](../references/asset-generation.md) · [分层拟合](../references/asset-fit.md)

**需要提供：** 图片在界面里的用途、目标显示大小、矩形预算以及哪些细节必须保留。没有输入图片时，先准备可使用的图片；工具说明中的示例参数不代表已生成的游戏素材。
