# 运行要求与验证

| 项目 | 要求 |
| --- | --- |
| 操作系统 | 完整包面向 Windows x64，随包模拟器依赖 Windows 原生模块。 |
| Python | 插件运行环境使用 3.11 或 3.12，安装器通过哈希锁创建专用虚拟环境。 |
| Node.js | 安装程序检查 22+，DeepSeek Harness 接入检查 24.9+。手动配置环境时请自行确认版本。 |
| 客户端 | 安装指南覆盖 Codex、Claude Code、DeepSeek Harness 和若干可尝试导入本地插件的客户端。可单独使用命令行。 |

安装完成后，在新会话中确认插件已启用，再做一次初始查询。[安装指南](installation.md) · [独立运行环境](runtime-environment.md)

## 验证分层

1. **静态检查**。解析语法和文件结构，核对已支持的字段、端口、API 签名及素材预算。
2. **离线模型与预览**。在本机运行已覆盖的 Lua、节点逻辑或软件渲染，检查模型行为和参考图。
3. **千星奇域编辑器导入**。实际打开产物，核对对象、挂载和脚本映射，并按需要保存再回读。
4. **游戏内运行**。在实际游戏里验证目标设备输入、渲染、多人同步和真实存档重进。
5. **试玩验收**。由创作者或试玩者确认手感与玩法是否达到制作目标。

每项结果适用于当次实际检查的输入和环节。反馈时附上版本、复现步骤、检查到的环节及报告。[详细验证说明](../references/validation.md)

## 报告状态

- `passed` 表示当前输入和范围内已执行并通过。
- `failed` 表示已执行，发现错误。
- `not_checked` 表示尚未执行或工具无法覆盖。
- `not_applicable` 表示该项与当前输入或工作流无关。
