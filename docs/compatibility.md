# 运行要求与验证

这里汇总完整工具包的**环境要求**和**验证分层**，方便在安装或排障时快速判断问题出在环境、本地工具还是游戏宿主。

## 环境与客户端要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| **操作系统** | Windows x64 | 完整包目标平台（随包模拟器含 Windows 原生依赖）。其他系统可查阅资料并运行部分纯标准库脚本 |
| **Python** | 3.11 或 3.12 | 安装器按哈希锁建专用虚拟环境；3.10 在安装前即拒绝 |
| **Node.js** | 22+（DeepSeek Harness 需 24.9+） | 用于本地 MCP 启动器、GIL 工具与随包模拟器 |
| **客户端接入指南** | Codex、Claude Code、DeepSeek Harness，以及提供本地导入步骤的其他客户端 | 具体接入方式见 [安装指南](../references/installation.md)；仅用命令行时见 [独立运行环境](../references/runtime-environment.md) |

装完后请在新会话中确认插件已启用，并先跑一次简单的 API 查询验证本地工具连通。

## 五级验证模型

工具包把验证拆成五个独立层级，低层级通过不自动等同于高层级通过：

1. **静态检查（Static）**：语法解析、文件结构、字段保留、端口类型、API 签名与像素/预算约束核对。
2. **离线工具（Offline Model / Preview）**：Lua 5.3 本地运行、受限节点图模型或软件渲染 PNG 预览，用于检查已覆盖的逻辑与渲染效果。
3. **编辑器导入（Editor）**：在千星奇域编辑器中实际打开目标文件，检查挂载、映射、节点展开和保存回读。
4. **游戏宿主（Host）**：在实际游戏环境中测试 PC/移动端输入、帧率、渲染细节、多人同步与跨局存档。
5. **使用者验收（Playtest）**：实际试玩，确认手感和玩法体验达到制作目标。

## 如何看懂报告里的状态

工具输出里常见的状态字段含义如下：

* `passed`：在当前源码与输入摘要下实际执行并通过。
* `failed`：实际执行了该项检查，发现错误。
* `not_checked`：该项检查尚未执行或当前工具无法覆盖。

* `not_applicable`：该项检查不适用于当前输入或工作流。

反馈问题或提交验证记录时，写明平台/客户端版本、复现用例、实际跑到第几级以及哪些环节未测，排查效率最高。更细的证据规范见 [详细验证说明](../references/validation.md)。
